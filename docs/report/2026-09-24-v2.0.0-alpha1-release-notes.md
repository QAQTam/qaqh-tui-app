# qaqh-tui v2.0.0-alpha1 发布说明（2026-09-24）

> 预发布。首个 alpha，用来验证「前端显示 chat 与工具、后端基本工具链跑得通」。

## 1. 这个版本是什么

**默认 UI 换成 V2 Agent View，协议仍是 Ringing v1。**

- 默认进入 V2 Agent View（inline viewport + scrollback 提交模型）；
- `--v1` 强制回退 v1 全屏，保留为 2.0 兼容面；
- `--v2-agent` / `QAQH_V2_AGENT` 保留为显式写法。

**协议为什么还是 v1**：后端冻结语义裁决第 1 条 —— 「v2 是 **beta** 起的权威重连
协议；v1 继续保留，但只作为 2.0 兼容面」。alpha1 不在协议切换点上，Ringing v2
的 SessionModel reducer 已随本版入库，但**尚未接线**（beta 才启用）。

## 2. 基本可用验收（上边的口径）

口径：「前端侧显示 chat 和工具基本正常，后端基本功能比如编辑/读写/bash 等工具正常」。

`scripts/e2e-alpha1-basic.sh` 把它变成可复现判据：**一个真实回合**里依次跑
`write` → `read` → `edit` → `exec`（bash），链路全真（TUI → daemon → provider →
工具执行 → 回灌 → TUI 渲染），只有"模型说什么"由本地 fake provider 脚本化。

```text
[✓] ① 前端显示 chat 正文
[✓] ② 前端显示四个工具名（write/read/edit/exec）
[✓] ③ 后端 write→edit 落盘为 v2 内容（读盘判据）
[✓] ④ 工具结果回灌 provider（role=tool）
RESULT: PASS
```

> ⚠ 诚实标注：本机无任何真实 provider 凭据，上述回合的**模型输出是脚本化的**。
> "真实模型下自行决定调工具"这条路径本轮**未验证**。

## 4. 本版修掉的、值得单独点名的缺陷

1. **默认 UI 的第一个动作整条失效**：空会话下按 `Ctrl+N` 屏幕毫无变化，再按一次
   又多建一个会话。根因是"新会话靠 `Created` 可靠事件开 tab"这条路径实践里不
   成立；已改为列表兜底 + 在途提示，并加 `e2e-new-session.sh` 钉住。
2. **三个老 e2e harness 被默认 UI 打哑**：`e2e-lease-expiry` / `e2e-restart` /
   `e2e-session-list` 仍用 `script(1)` 驱动 PTY，不答 `ESC[6n` 光标查询 → TUI
   初始化即 panic（假红）。已抽出 `scripts/lib/pty-driver.py` +
   `scripts/lib/vt_screen.py` 统一修掉。

## 5. 已知限制（请一并发布）

- **v2 协议未启用**（beta 才切）；v2 reducer 已入库但未接线；
- **v2 Agent View 空态不显示连接相位**：`status_line` 只在有活动会话时绘制；
- **多标签 + 子代理并发未验证**：需要真实 LLM；
- **真实模型路径未验证**：本轮所有 e2e 的模型输出都是脚本化的；
- **Alacritty 仅进程级支持**（其余终端不逐个支持，见终端兼容矩阵）。

## 6. 运行

```bash
cargo build --bin qaqh-tui          # 需要 ../qaqh-backend 与 ../ratatui 两个兄弟仓
./target/debug/qaqh-tui             # daemon 未运行时自动尝试拉起 qaqh-daemon run
./target/debug/qaqh-tui --v1        # 回退 v1 全屏
```

环境变量：`QAQH_DATA_DIR`（数据目录）、`QAQH_BACKEND_ROOT`（daemon 候选根）、
`QAQH_THEME`（night/day/terminal/auto）、`QAQH_TUI_LOG`（诊断日志落盘路径）。

## 7. 回滚

`--v1` 即可回到 v1 全屏；UI 默认切换在 `src/main.rs::select_startup_mode` 一处，
如需整仓回退，回滚到 `9c12f4d`（alpha1 之前 main 的 tip）。
