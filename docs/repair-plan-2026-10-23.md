# 修复与功能补全计划

日期：2026-10-23。依据：[项目审计](audit-2026-10-23/README.md)、[性能交接](../HANDOFF-PERFORMANCE.md)、[现有 v2.0.1 体验规范](spec-v2.0.1.md)。本文件是实施计划；下列任务尚未执行。

## 目标与工作约束

按顺序达到四个结果：输入和凭据不会丢失或串入其他目标；失败、预览和截断有准确反馈；连接、设置与权威后端契约一致；长会话可持续使用，并完成消息区精简。

- 保留现有脏工作区，先记录差异；不要 reset、覆盖或替别人提交已有修改。后端也有未提交配置改动。
- 全部在主会话实施，不使用子代理。默认 debug、离线、单 job 增量验证。
- 不重启当前用户实例，不写真实凭据或配置；端到端测试使用独立数据目录、端口与假数据。
- 传输、证书与协议扩展进入 `qaqh-client` 等权威后端 crate，TUI 不另建 HTTP/SSE 客户端或协议镜像。
- 本地显示偏好只进 `LocalConfig`。性能模式的正文简化仅在性能模式启用，动效模式保留完整 Markdown。
- 一个任务尽量对应一个可审查提交；有明确依赖的跨仓变更采用“后端提交 → TUI 适配 → 发布清单同步”。
- 范围分为“修复必须完成”“能力补全”“后续体验”。发布验证要求覆盖实际发布范围，不能用未实现的可选功能阻塞修复。

验收：原有 598 条测试基线可复现；所有审计项有归属任务；固定依赖与本地依赖的差异有记录。最终 pin 更新与干净检出构建在 R20 验收。

## 批次 1：凭据、草稿和失败恢复

### R01 · 统一粘贴目标〔必须，F01〕

主要位置：`app/mod.rs::handle_paste`、`overlay_ops.rs`、`remote_ops.rs`。

- [ ] 按当前可见路由和输入焦点决定接收者，优先级与键盘、鼠标一致；阻塞式 permission/ask/plan 也纳入裁决。
- [ ] 补齐 Remote Token/URL/设备名、CwdInput、AttachPath、Settings 编辑缓冲与自定义回答。
- [ ] 有覆盖层但没有可编辑目标时消费粘贴；不会回落底层 composer。按光标位置插入，单行输入统一去除 CR/LF。

验收：有/无活动会话两种情况下，粘贴只修改可见目标；Token 不出现在聊天、toast 或日志；无输入覆盖层与观测模式不改变隐藏草稿；粘贴不会自动提交。

### R02 · 移除 Windows 浏览器 shell 路径〔必须，F02〕

主要位置：`app/browser.rs`、账号 URL 调用点。

- [ ] Windows 使用原生 URL 打开能力或不经过 shell 的可靠封装，删除 `cmd /C start`。
- [ ] 用 URL 解析与 scheme 校验确定可打开链接，保留合法 OAuth 多查询参数、百分号编码和 Unicode。
- [ ] 浏览器启动错误可见；避免在错误日志中打印含授权材料的完整 URL。

验收：Windows 原生环境验证正常 OAuth URL；`&`、`|`、引号、百分号等输入不会改变执行语义；`file:`、`javascript:` 与控制字符被拒绝。Linux/macOS 的 URL 参数保持原样且不进入 shell。仅验证 URL 门禁不足以关闭本项。

### R03 · pager 临时文件保密与可靠清理〔必须，F13〕

主要位置：`app/pager.rs`、`terminal/agent/mod.rs::run_pager`。

- [ ] Unix 创建时直接使用 0600，文件置于用户私有临时目录；保留独占创建，使用可靠的生命周期清理。
- [ ] 成功、启动失败、终端恢复失败等正常错误路径均清理；明确崩溃残留的处理方式。Windows 验证用户私有目录与权限。
- [ ] `sh`/默认 pager 缺失时给出可见反馈或平台可用的安全回退；不假定所有 Windows 都安装了 shell。
- [ ] 保留现有正文控制序列清洗。

验收：umask 022 下仍无组/其他用户读权限；失败路径不遗留测试文件；没有恢复终端输入失败或正文转义注入回归。

### R04 · 按命令保存发送内容，保护新草稿〔必须，F06〕

主要位置：`transcript_ops.rs::send_message`、`app/mod.rs` 的 ActionResult/CommandAck、`session.rs`。

- [ ] 发送前生成并保留 command_id，以会话及命令身份存储待发送文字和附件，回包携带该身份。
- [ ] 区分确定拒绝、确定未送达、结果未知、已受理/已完成；HTTP ack 不充当最终业务成功。
- [ ] 确定失败时保留可恢复内容。若用户已有新草稿，提供“恢复未发送内容”入口，不能直接覆盖。
- [ ] 删除所有命令拒绝时把错误文案写进 composer 的通用逻辑；错误仍通过状态/消息反馈。
- [ ] 结果未知先核对 receipt/权威消息状态，不自动重复发送；附件引用保留到结果可判定。

验收：发送失败保留文字与附件；发送后继续输入、连续两笔发送、回包乱序、关闭会话再返回均不会串单或覆盖。取消/切模式/撤销等命令被拒绝不改 composer。同一命令对账后不会产生双份用户消息。

### R05 · 设置保存采用提交快照与编辑代际〔必须，F07〕

主要位置：`settings.rs`、`settings_ops.rs`、`app/mod.rs::ConfigWrite`。

- [ ] 为设置面板实例、提交请求和字段编辑记录身份/代际；回包只确认本次提交的字段。
- [ ] 只清除提交后没有再次编辑的字段。不能仅比较值是否相等，需覆盖 A→B→A 的再次编辑。
- [ ] 关闭重开面板后，旧回包可以刷新 loaded，但不清除新面板草稿；并发 config.load 不把较新本地结果回滚。
- [ ] 本地偏好保存与 daemon 保存分开反馈；混合保存失败明确哪部分已成功。合并未来 LocalConfig 新字段时保留其他本地偏好。
- [ ] 凭据来源切回 BYOK 恢复原端点/wire 草稿；账号摘要与模型目录按当前来源及请求身份更新，迟到旧目录不串档。

验收：保存期间继续编辑、关闭重开、回读失败、多端刷新均保留新编辑；apiKey 不回显；仅改本地项不发 config.save/load；BYOK→账号→BYOK 往返不意外改路由。

### R06 · 交互应答保留在途状态，失败后可恢复〔必须，F03〕

主要位置：`interaction.rs`、`session.rs`、`app/mod.rs`、`ApiCtx::send_interaction_command`。

- [ ] 使用 interaction/call id + command_id 保存面板、输入答案、决策及在途状态；等待中禁用重复操作并显示进度。
- [ ] suppression/“已解决”只在有可靠终态依据时落定，不能等同于“刚点击发送”。
- [ ] 确定拒绝/未送达恢复原面板；超时先对账 receipt 和 pending 状态，未知时显示“确认中”，保留内容。
- [ ] 已被其他客户端解决、已过期或工具已完成时关闭旧面板，迟到失败也不能重新打开它。

验收：ask、permission、plan 分别覆盖失败、超时、成功、其他客户端先答、回包晚到与 bootstrap 重载；不重复授权、不重开终态交互；拒绝理由、自定义答案和信任目录选择不丢失。对账必须有退避/上限及可见恢复入口。

## 批次 2：输出准确性与消息完整性

### R07 · 工具输出采用跨分片解析状态〔必须，F08〕

主要位置：`timeline_model.rs::apply_bash_progress`、ToolCard。

- [ ] 普通片段追加；只有明确的 CR 语义才覆盖当前行。将 CR、CRLF、ANSI 不完整序列状态保存在工具流中。
- [ ] 快照、工具终态替换和重基线重置解析状态；快照自身也能正确建立后续追加状态。
- [ ] 保留有界 progress 缓冲，并记录截断、累计字节与流标识。stdout/stderr 按权威契约保留身份，不凭片段猜测。

验收：`hel`+`lo\n` 为 `hello\n`；CR 进度正确；CRLF/ANSI 跨边界、多字节字符、不完整转义与超长单行分片一致；随机分片结果与一次性输入一致；截断可见且无 UTF-8 边界错误。

### R08 · 持久展示失败、预览和截断〔必须，F09/F10/F11〕

主要位置：`adapter.rs`、`transcript.rs`、`timeline_model.rs`、`fullscreen.rs`。

- [ ] 把 Turn.failure/终态转成持久消息；canonical 与 timeline 的同一失败去重，理由晚到可以补齐。区分失败、中止和成功。
- [ ] offloaded 回合显示“仅预览”，复制/导出明确当前是否完整；核实后端全文读取能力后接按需加载，缺少能力时明确展示限制。
- [ ] 将 progress/body/outcome 的截断事实传入显示模型；正文为空或摘要被去重时仍能显示提示。
- [ ] 将新可见状态纳入外层及块级缓存失效，避免状态变化后仍显示旧卡片。

验收：模型请求在零正文时失败也能看到理由；重复/乱序终态不产生重复错误；offload 预览不会伪装全文；复制与导出不静默称为完整；短正文、空正文、展开与折叠均保留截断提示。

### R09 · 折叠工具卡限制视觉高度〔必须，F12〕

主要位置：`transcript.rs::render_tool_body`、查询工具分组与命中登记。

- [ ] 成功折叠卡按视觉行数限制预览，使用现有三行作为初始正文预算；头部、展开提示与必要错误状态独立计入布局。
- [ ] 普通输出保留尾部、diff 保留开头等既有语义；running/failed/cancelled 各自有明确策略。
- [ ] 先按需要选取/布局预算范围，避免为三行预览构造全文的深拷贝及折行结果。

验收：6000 字符单行在 80/40 列均保持折叠预算；展开可查看保留内容；错误、截断状态始终可见；折叠/展开后滚动锚点、菜单、鼠标命中与实际行一致。

## 批次 3：连接与订阅生命周期

### R10 · 由协调器管理连接、订阅和异步归属〔必须，静态风险 1/2〕

主要位置：`runtime.rs`、`remote_ops.rs`、`app/mod.rs` 的异步消息入口。

- [ ] 使用连接 generation 和最新 wanted 集合协调 activate/deactivate；激活、attach 重试可取消，在异步完成时再次验证归属。
- [ ] 快速 A→B→A 不留下屏外订阅、不重复建流；在途激活完成后发现已取消时可靠清理。
- [ ] 切目标先验证新连接再交接；失败保持旧连接，或明确进入 Lost，不能只还原地址却保留已关闭 client。
- [ ] 成功切 daemon 时区分目标命名空间；旧目标的事件、配置、账号/配对回包、会话任务不能作用于新目标。
- [ ] 只有切换成功才执行恢复；同一目标重连与切换不同目标分别定义恢复策略。旧目标草稿/历史保留为明确绑定的数据，不能误发给新目标。

验收：用可控延迟的假服务/传输夹具验证激活晚于撤销、401 重试途中离开、重连失败、旧回包晚到；稳定后实际订阅等于 wanted，无静默残留任务。无需访问用户正在运行的 daemon。

### R11 · 完成远端 HTTPS 与证书信任〔必须，F05；依赖 R10〕

后端位置：`qaqh-client` 连接选项与 HTTP 客户端构建；TUI 位置：RemoteTarget、Remote 页面、CLI。

- [ ] HTTPS 使用系统信任链；默认不关闭证书验证。
- [ ] 自签 LAN 场景使用后端权威指纹格式与算法完成验证，指纹由可信渠道输入/配对取得。不要重新定义一套“指纹”。
- [ ] HTTP 默认只供明确的 loopback/本地隧道场景；去掉“把 LAN 地址改成 HTTP”的误导。若保留高级明文部署能力，必须显式启用且不自动降级。
- [ ] URL 解析覆盖主机、端口、IPv6、禁止内嵌凭据与非法路径；CLI、页面、环境变量共用规则。
- [ ] 核对实际使用的 TLS 后端是否支持所选系统信任/自签方案；后端扩展完成后再同步 TUI 的固定依赖。

验收：可信 HTTPS 可连；自签未信任拒绝、正确 pin 成功、错误 pin/轮换后拒绝；Bearer 不进 URL/日志；TLS 失败不降级；旧 loopback 本地连接正常；CLI 与 UI 配置行为一致。

## 批次 5：有证据的性能优化

### R14 · 建立可重复性能基准〔必须先于 R15–R17〕

- [ ] 使用同一构建模式、固定夹具与固定终端尺寸，记录空闲、长正文流式、代码流式、多会话切换和深分页。
- [ ] 采集模型/渲染缓存字节、事件积压、输入到可见帧延迟、单帧布局耗时、解析次数与处理字节数；同时记录 RSS/CPU 观测边界。
- [ ] 固定 80/120 列，10/100/1000 KiB 文本，中英文、长单行、表格/代码、不同分片大小，保留 resize/重基线场景。
- [ ] 以基线确定具体帧预算和内存预算，记录硬件、debug/release、样本和分位值。

验收：同一夹具能重复对比修改前后；有工作量计数，不能只凭一次 wall-clock。现有 spec 中的 <3ms、<35MB、0% CPU、<10ms Resume 均作为待验证目标，不作为已经满足的事实。

### R15 · 仅性能模式启用轻量增量正文〔依赖 R07/R08/R14〕

- [ ] reducer 提供 Append/Replace/Reset 变更事实；稳定文本前缀只布局一次，不用每片全文 starts_with/hash 来伪装增量。
- [ ] 性能模式助手正文走独立轻量布局；动效模式保持完整 Markdown/语法高亮，原文用于复制与导出。

- [ ] 处理字素尾部、CJK、emoji/ZWJ、组合字符、CRLF、Tab 与跨片转义；`qaqh-ui` 围栏无论怎样切片都不泄漏 DSL。
- [ ] 封口时维持当前显示模式，避免突然全量解析和行高跳变；如需另加“查看完整 Markdown”，由用户显式触发。

验收：正常追加累计处理量接近总新增字节，稳定前缀不反复解析；性能模式不调用 Markdown/syntect；随机分片与一次性结果一致；动效模式与原有输出一致；内存不新增另一份无限增长的完整正文与平铺行数组。

### R16 · 事件处理预算与队列背压〔依赖 R10/R14〕

- [ ] 区分可靠事件、可替换状态与输入，保留每个会话内的顺序及交互身份语义。
- [ ] 主循环每批有消息数/时间预算，持续流量下仍能处理输入和绘制；只合并契约允许替换的状态。
- [ ] 结合客户端回调接口设计有界缓冲/背压，必要时改 SDK；禁止在 tokio 同步回调里直接使用可能阻塞或 panic 的 blocking_send。
- [ ] 队列过载可观测，恢复不能静默丢 timeline。鼠标事件仍基于已发布帧校验，避免提优先级后点到状态已变的旧坐标。

验收：生产者持续快于消费者的压力测试中，队列/内存受控，可靠事件有序无丢失；输入延迟不随积压无限增长；断连/关闭无死锁；正常负载不增加可感知绘制延迟。

### R17 · 模型与缓存采用可见字节预算〔依赖 R08/R10/R14〕

- [ ] 分别统计 SessionState、工具/思考正文、渲染缓存和共享 Arc 的成本，避免重复计数。
- [ ] 优先回收不可见渲染缓存和可重新获取的历史；逐出旧模型时明确显示“更早内容待加载”，保留游标/锚点与正确重取路径。
- [ ] 在途交互、未发送输入、活动回合、待确认命令和用户当前可见区域不被误逐出。

验收：重复深分页、多标签切换与长流式增长后内存达到所设预算行为；重读内容正确，分页不重不漏；复制/导出明确完整性；关闭会话释放资源。不要重新引入静默按回合数量截断。
