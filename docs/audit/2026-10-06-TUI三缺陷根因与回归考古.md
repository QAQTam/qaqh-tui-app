## B1【已证实】todo 面板不随 `todo_update` 推进工作状态

**现象**：置顶 todo 面板停在模型最后一次「整表写」的瞬间，此后模型逐条改状态都不动。

**根因**：后端 todo 是三个工具，渲染侧只认其中一个。

| 事实源 | 名字门 | 位置 |
|---|---|---|
| 置顶面板（timeline 派生） | `name != TODO_TOOL_NAME` 精确匹配 `"todo_write"` | `src/ui/v2/transcript.rs:127`、`src/ui/v2/adapter.rs:209`、`src/ui/v2/adapter.rs:235` |
| workspace F4 面板（dashboard RPC） | `tool.name.starts_with("todo")` 松匹配 | `src/app/mod.rs:1027-1029` |

后端工具族与入参形状（`../qaqh-backend`）：

- `crates/qaqh-runtime/src/agent/plugins/dashboard.rs:13-15` — `is_todo_tool` =
  `todo_write | todo_update | todo_list`
- `crates/qaqh-workspace/src/todo/split.rs:71-90` — `handle_update` 是**单一形态**
  `{id, status, evidence?}`，「一次一条，多任务循环调用」，且 `reject_fields` 明确拒绝
  `items`

模型工作时的状态推进**全部**走 `todo_update`，在精确名字门就被丢弃；`current_todo()`
因此恒返回最后一次 `todo_write` 的入参。第二道锁：`TodoBlock::parse` 硬要求 `items`
数组（`src/ui/v2/transcript.rs:171-179`），`todo_update` 的入参没有 `items`——**只放宽
名字门不够**，必须把 delta 折叠上去。

错误假设写在代码注释里：`src/ui/v2/adapter.rs:219`「`todo_write` 是整表替换，所以最后
一次成功的入参就是全量」——只在 `todo_update` 不存在时成立。

**引入 commit**：`322fa3d`（2026-10-04，工具卡渲染重构）。`git grep -i todo_write
322fa3d^` 在 `adapter.rs` / `fullscreen.rs` / `transcript.rs` **零命中**：重构前根本没有
timeline 派生的置顶 todo，todo 只由 `session.dashboard` RPC 承载
（`322fa3d^:src/app/mod.rs:2107-2117`），而后端 dashboard 反映真实状态，那条路一直是对的。
所以这不是「实时刷新被改坏」，是**新面板出生就看不见 `todo_update`**；松匹配
`starts_with("todo")` 是重构留下的化石，也正是两个面板行为不一致的来源。

**测试为何没拦住**：`todo_tool_update_refreshes_dashboard` 这个「测 todo update」的用例，
自己把假工具命名成 `"todo_write"`（`322fa3d^:src/app/mod.rs:3663,3670`；现 HEAD
`src/app/mod.rs:4033`）。全套测试里从来没有一条真实 `todo_update` 事件——可核到的最强证据是
`grep -rc todo_update src/` **零命中**：整个 TUI 源码（含所有 fixture）从未出现过这个名字，
所以任何测试都不可能覆盖它。

**修形**：精确门换成家族谓词（对齐后端 `is_todo_tool`）；`current_todo` 按 timeline 顺序
把 `todo_write` 当整表替换、把 `todo_update` 按 id 折叠进保留的清单；为
`{id, status, evidence}` 单条目形状加解析入口；`src/app/mod.rs:1028` 用同一谓词，两个面板
收成一个事实源。

## B2【已证实】全局共享刷新率，且单帧代价随 transcript 线性增长

**现象**：文字流式输出时帧率低，动画帧率同样低，两者互相挤占。

**根因是两条，叠加生效——只做分区调度不会治好。**

1. **单一时钟。** `src/terminal/agent/mod.rs:52`
   `const TICK_INTERVAL: Duration = Duration::from_millis(200)` 是唯一能唤醒空闲循环的东西
   （`spawn_tick` `:190-200`）。`run_loop`（`:214-257`）每轮**无条件**画一整屏
   （`draw_and_publish` `:235-243`，没有任何 dirty flag 能跳过绘制），再
   `app_rx.recv().await`（`:248`）+ `try_recv()` 排空积压（`:252-257`）。动画又被写死到同一
   量子：`src/app/anim.rs:10` `as_millis() as u64 / 200`，`:51-52` 的注释直接写「保持与
   Tick 对齐」。没有任何分区调度器 → 空闲时整屏 5fps，且菊花**不可能**快过 200ms；漏掉的
   tick 在 `:252` 被合并成一批，连动画步数都拿不到。
2. **单帧 = O(整段 transcript)。** transcript 逐块 memoization 是有的
   （`FullscreenTranscriptCache::sync`，`src/terminal/agent/fullscreen.rs:882-989`），但缓存键
   含全局 `session.timeline.version`（`e00fff8` 引入，`:883-891`），而每个 token 都 bump
   version（`src/app/timeline_model.rs:484-487`）→ 每个 token 批次重跑全量重建：逐块
   `text.clone()`（`src/ui/v2/adapter.rs:177-190`）、缓存行 `.cloned()` 灌进全局 Vec
   （`fullscreen.rs:980`）、hit span 全表重建、`sync_todo` 全表重扫（`:747-759`）、
   `fullscreen_layout` 每帧跑两遍（`:192` 与 `:435`/`:605`）。活块自身每次 miss 重解析整段
   markdown（`src/ui/v2/markdown.rs:477`）。`force_redraw`（TurnSealed / TurnFinished，
   `src/app/mod.rs:1046`）另加一次 `terminal.clear()` 全终端重 flush。

blit 层走 ratatui 的 buffer diff（`terminal.draw` `src/terminal/agent/mod.rs:362-364`），
**没有**应用级分区 / dirty-rectangle 渲染，widget 恒画整个 `frame.area()`。

**引入 commit**：不是回归，是三个提交叠出的原始架构。

| 元素 | 引入 |
|---|---|
| `TICK_INTERVAL = 200ms` 单时钟 | `d0f51e2`（2026-09-20，`feat(v2): M4.1 agent inline shell`） |
| `anim.rs` 的 `/ 200` 量子 | `a4a45eb`（2026-09-02，**早于** tick，后被对齐） |
| 缓存键含全局 `timeline.version` | `e00fff8`（2026-09-24） |

`322fa3d` 是**缓解**（新增逐块 memoization），`b0616ed` 只拆 markdown 模块，两者都不是元凶。

**修形**：动画需要自己的重绘触发与不被量化的相位（由 `Instant` 差值驱动，别再用 `/200`）；
`run_loop` 需要能跳过绘制；transcript 缓存要按「脏尾块」增量而非按全局 version 失效，使一个
token 的成本降到 O(可见行)；流式重绘可另设一个与动画 tick 无关的最小间隔门。

## B3【管道完整，命中点待运行时定性】ask 不弹出任何面板

**先说结论**：静态读码**排除了**所有结构性断点——所以问题在三个静默出口之一，而当前默认
配置下静默出口不可见。

已排除（逐条核过）：

- `kind` 字面量两侧**字节一致**：生产方 `../qaqh-backend/crates/qaqh-domain/src/interaction_body.rs:21`
  `"kind": "ask"` ↔ 消费方 `src/app/mod.rs:1610` `match kind { "ask" => {`。TUI 从不按工具名分派。
- `questions` 的解析类型 `qaqh_client::DomainAskQuestion` **就是**后端序列化它用的那个
  struct 的再导出（`../qaqh-backend/crates/qaqh-client/src/types.rs:20` → `qaqh-domain::AskQuestion`），
  两侧同一份定义，不可能形状漂移。
- wire 枚举与匹配一致：`../qaqh-backend/crates/qaqh-session/src/session_fact_v2/projection_event.rs:735-742`
  的 `ControlDelta::InteractionRequested` 字段与 `src/app/mod.rs:1338-1344` 一一对上。
- 路由 / 绘制 / 键位齐全：`src/ui/v2/route.rs:58`（挂起交互优先级最高）、
  `src/ui/v2/modal.rs:250-257` → `draw_ask`（`:965`）、`src/app/interaction.rs:352-399`
  （←→↑↓ / Enter / Space / 1-9 / a-f / e / z / Esc）。渲染门控只有
  `modal.rs:977` `rect.width < 8 || rect.height < 4`，正常尺寸不可达。
- 无 auto-approve / yolo / bypass 短路（全仓 grep 零命中）。
- 正文下载失败**会** toast：`src/app/mod.rs:1975-1978`「交互正文取回失败」。
- ask 状态机与 drawing 都有通过中的测试（含 `modal.rs:1594` 的 ask 渲染用例）。

### 3.1 三个静默出口（候选命中点）

| # | 位置 | 静默程度 |
|---|---|---|
| 1 | `src/app/ringing_v2.rs:314-321` 单一 canonical cursor `(fact_seq, projection_index)` 判 `Stale` | 只有 `log::warn!` |
| 2 | 同上 `:316-317` `Duplicate` 分支 → `src/app/mod.rs:1264` 返回 `false` | **连日志都没有** |
| 3 | `src/app/mod.rs:1484` `ContentValue::Unavailable(_) => {}`（另 `:1537` 同形） | 无日志、无 toast |

而 `src/main.rs:20-31` 写明：默认**不装 logger，`log` 门面是空操作**，只有设
`QAQH_TUI_LOG=<path>` 才落盘。所以线上看到的正是「什么都不出现」。

### 3.2 引入 commit：`88ab38f`（2026-09-24）

`feat(v2)!: consume the per-seed canonical event stream`。重构**前**，问题清单是事件上的
强类型字段（`88ab38f^:src/app/mod.rs:1181-1189`）：

```
ControlEvent::InteractionRequested { interaction_id, turn_id, mode, questions }
    → AskPanel::new(interaction_id, turn_id, mode, questions)
```

改为「从 content store 下载 JSON body、按顶层 `kind` 字符串分派」后，一次性生成了 §3.1 的
出口 2、3（同日 `41355e6` 落了单一 cursor 即出口 1），并**丢了字段**：旧路径透传 `turn_id`，
新路径写死 `String::new()`（`src/app/mod.rs:1618`）。

### 3.3 两个已证实的次生缺陷（无论命中哪个出口都要修）

- **空清单键盘陷阱**：`src/app/interaction.rs:338-340` 在 `questions` 为空时对**每个键**返回
  `true`（= 已消费），`src/app/mod.rs:2330-2334` 的阻塞 Modal 门据此 `return` 短路
  `handle_key` → Esc/Dismiss（`interaction.rs:538`）与 Enter/`submit_ask`（`:542`）都不可达；
  鼠标侧同样被 `register_modal_root`（`modal.rs:980`）挡住点击穿透。渲染侧
  `ask_rows`（`modal.rs:838-840`）返回空 Vec，只剩一个边框。症状即「问不出来、也关不掉」。
  此缺陷更老，来自 `efa05d9`（2026-09-20）。
  **边界要说准**：只有 `GlobalKey::QuitArmed | QuitNow` 两个全局退出键能绕过这道门
  （`mod.rs:2331`），所以面板不是完全无法离开，而是**无法用 Esc/Enter 正常答复或关闭**。
- **解析没有地板**：permission 有（`src/app/session.rs:735-770`，逐字段
  `#[serde(default)]` + 占位文本「（恢复中）」，畸形正文仍渲染出可关的面板）；ask 与 plan
  没有——`src/app/mod.rs:1615` 与 `:1635-1640` 直接 `unwrap_or_default()`，任何正文异常都被
  归零成空面板。

### 3.4 定性判据（下一步）

带 `QAQH_TUI_LOG=<path>` 复现一次 ask，看落点：出现 `drop v2 event for <session>: Stale` /
`… Duplicate` ⇒ 出口 1/2（cursor 语义与 fan-out 的 `projection_index`  ordering 冲突）；
两者都没有且无 toast ⇒ 出口 3（正文 `Unavailable`，即 content store 那次写没落地）。
在此之前，本文不把任何一条写成结论。

### 3.5 修形

把 ingress 变响：`apply_interaction_body` 的 `else { return }` / `_ => {}` 一律
`log::warn!` + `NoticeLevel::Warn` toast，带上 `session_id` / `interaction_id` / `kind`；
`request_interaction:1484`、`restore_pending_interaction:1537`、`mod.rs:1264` 的 `Duplicate`
同待。给 ask 一个类型化地板（`from_value::<AskBody>` + `#[serde(default)]`），并把
「零个问题」当错误处理——用 body 的 `title`/原文造一个 `allow_custom = true` 的兜底问题，
而不是 `Vec::new()`。拆掉陷阱：`questions` 为空时落到 `D::Dismiss` 分支，别返回 `true`。

## 4. 缺陷一览

| 编号 | 现象 | 根因一句话 | 引入 | 严重度 |
|---|---|---|---|---|
| B1 | todo 不随 `todo_update` 实时变动 | 渲染侧精确名字门 `== "todo_write"`，而协议有 `todo_update`/`todo_list`；`TodoBlock::parse` 又硬要求 `items` | `322fa3d` | 功能缺陷，确定性最高 |
| B2 | 全局共享刷新率，文字流式时动画与帧率一起掉 | 单 `TICK_INTERVAL=200ms` + `anim.rs` 同一量子 + 无 dirty flag + 缓存键含全局 `timeline.version` 使每帧 O(transcript) | 非回归（`a4a45eb`/`d0f51e2`/`e00fff8` 叠加） | 性能/架构 |
| B3 | ask 完全不弹面板 | 管道完整；三个静默出口之一被命中，默认无 logger 因而不可见 | `88ab38f`（次生缺陷 `efa05d9`） | 阻塞交互，**待运行时定性** |

## 5. 未提交 WIP（记录时的工作区，非本文三缺陷的成因）

`git status` 六个文件被改：`Cargo.lock`、`src/app/timeline_model.rs`、
