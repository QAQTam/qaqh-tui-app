# `SPEC-v2.0.1`: 会话抽屉、Hover 实时待办与极速 Resume 规划规范

* **版本标识**：`v2.0.1`（体验反超与人机工程学升维）
* **定位愿景**：*“丢掉沉重 Webview，在极简终端上实现桌面级现代交互”*
* **性能基准**：在低配机型（如 2C2T G2020、树莓派等）上保持常驻内存 **< 35MB**，全帧渲染控制在 **< 3ms**，零空闲 CPU 占用。

---

## 一、背景与设计动机

在 `v2.0.0` 实现了 OAuth 契约对齐、动态真实模型目录和鼠标点选之后，当前 TUI 面临的核心痛点集中在“会话管理与跨任务交互”体验上：

1. **会话管理割裂**：
   * 左侧常驻侧栏（Rail）常驻占据 24~32 列，不可折叠收起，信息密度低；
   * `Ctrl+L` 触发的全屏黑色 Modal（`Overlay::SessionList`）彻底遮挡当前对话与工作区，切断了编码和问答的心流；
   * 两套 UI 都负责会话管理，逻辑与感知割裂。
2. **缺乏待办状态反馈（未能对齐桌面端）**：
   * 当后台会话处于“等待工具授权”（`waiting_permission`）、“等待回答”（`waiting_ask`）或“等待计划评审”（`waiting_plan`）时，TUI 仅显示静态黄色小菱形 `"◆"`；
   * 用户无法在不切入会话的情况下得知被什么工具卡住，鼠标悬停时没有任何反馈。
3. **`resume` 启动动线生硬**：
   * 命令行执行 `qaqh-tui resume` 粗暴弹起全屏黑底列表；
   * 欢迎首屏（Brand View）将“继续上次”堆叠在主输入框上方，打乱了自上而下的视觉焦点。

## 二、模块一：会话管理合流 —— 可折叠侧边抽屉（Collapsible Drawer）

### 1. 设计目标
* 彻底退役全屏黑底 Modal，将全部会话查看、切换、归档、工作区过滤能力统一收口进左侧侧边抽屉。
* 全面践行“Mouse-Controller First”，支持鼠标一键折叠展开。

### 2. UI 形态线框图

```text
 ┌── 沉浸编码模式 (收起态: 宽度 0) ────────────────────────┐
 │ [ ≡ ]  ● 晚间问候                       22:45  [Ctrl+,]│
 │ ────────────────────────────────────────────────────── │
 │                                                        │
 │   整个终端 100% 留给正文与代码阅读（视野完全拉满）        │
 │                                                        │
 └────────────────────────────────────────────────────────┘
                           ↕ 鼠标点击 [ ≡ ] 或按 Ctrl+L
 ┌── 会话抽屉模式 (展开态: 宽度 28~32) ───────────────────┐
 │ [ ≡ ] 会话管理      [+ 新建] │ ● 晚间问候     22:45   │
 │ ────────────────────────────┼───────────────────────── │
 │ 过滤: [全部工作区 ▾]        │                          │
 │  ● 晚间问候             [x] │                          │
 │  ◆ 猜测设备系统与硬件   [x] │  右侧正文与输入框        │
 │  ○ 历史编译器调试           │  始终可见、实时交互      │
 │ ────────────────────────────┤                          │
 │ [ c 仅看当前目录 ]          │                          │
 └─────────────────────────────┴──────────────────────────┘
```

### 3. 技术规范与状态机
* **状态定义**：
  在 `App` 结构体中引入 `pub sidebar_collapsed: bool`，并在 `LocalConfig` 中持久化用户的折叠偏好。
* **展开逻辑**：
  * **宽屏（`terminal_width >= 90`）**：
    * 折叠态：侧栏宽度为 `0`，正文占据全宽；
    * 展开态：侧栏占据标准 28 列（宽屏自适应至 32 列），正文右移；
    * 切换触发：左上角汉堡图标 `[ ≡ ]` 注册 `PointerTarget::Workspace(WorkspaceHit::ToggleSidebar)`，或全局按键 `Ctrl+L`。
  * **窄屏（`terminal_width < 90`）**：
    * 默认恒定收起（宽度 0）；
    * 唤起时作为 **浮层抽屉（Overlay Drawer）** 悬浮覆盖在左侧，右侧区域注册“点击空白处收回”（Click Outside to Dismiss）区域。
* **行级快捷操作**：
  * 鼠标 Hover 会话行时，行尾渲染微型 `[x]` 归档按钮，点击立即将目标会话归档。

## 三、模块二：实时待办徽标与鼠标 Hover 浮窗（Hover Tooltip）

### 1. 契约对齐
消费 `qaqh-client` 投影中的 `SessionRunStatus`（8 态）：
* `waiting_permission`：等工具授权（高危命令需人确认）；
* `waiting_ask`：模型提问等待输入；
* `waiting_plan`：计划评审等待确认。

### 2. 交互呈现规则
* **行内徽标**：
  * 普通运行中：播放 `anim::claude_spinner` 星芒旋转动画；
  * `waiting_permission`：黄色高亮徽标 `◆ 待授权`；
  * `waiting_ask`：蓝色高亮徽标 `◆ 待回答`；
  * `waiting_plan`：青色高亮徽标 `◆ 待确认`。
* **鼠标 Hover 悬浮浮窗（Tooltip）**：
  * 当鼠标指针悬停在某会话行（`view.pointer.sidebar_hover == Some(index)`）时，在其右侧无遮挡空白处绘制轻量级浮层：

```text
 ┌── 侧边栏 ──┐  ╭── 会话待办提醒 ────────────────────╮
 │            │  │ 会话：设备猜测                     │
 │ ● 晚间问候  │  │ 状态：⚠️ 等待工具授权              │
 │ ◆ 设备猜测──┼─>│ 工具：exec                        │
 │            │  │ 命令："cargo check -j 1"           │
 └────────────┘  │ 操作：[点击立刻切入处理]           │
                 ╰────────────────────────────────────╯
```

## 四、模块三：Resume 直跳与欢迎首屏动线重构

### 1. `qaqh-tui resume`：极速直跳恢复（Direct Jump）
* **命令行核心行为**：
  1. 启动时扫描当前 `initial_cwd` 目录下 `updated_at` 最近的活跃会话；
  2. 若找到，**直接将其挂载为当前活动会话并渲染正文，跳过任何中间选择页面**（耗时 `< 10ms`）；
  3. 展开左侧抽屉并高亮定位该会话；
  4. 底部弹出 Toast 确认：`已直接恢复会话「XXX」 (按 Ctrl+L 或点 [≡] 切换)`；
  5. 仅当当前目录下没有历史会话时，优雅退回欢迎首屏。

### 2. 首屏（Brand View）视觉重心下沉
* **痛点改进**：将历史会话卡片从输入框上方，**下移至主输入框下方**，符合先输入、后历史的浏览动线：

```text
        ╭──────────────────────────────────────────────────╮
        │ > 描述你的需求，或输入 / 唤起命令...              │
        ╰──────────────────────────────────────────────────╯

         ▸ 继续上次工作 (鼠标点击 或 按数字键直接进入):
         ┌────────────────────────────────────────────────────────┐
         │ [1] ● 晚间问候 · 刚刚                         [当前目录]│
         │ [2] ● 猜测设备系统与硬件 · 2小时前            [当前目录]│
         │ [3] ○ 前端模型目录接口联调 · 昨天             [/backend]│
         └────────────────────────────────────────────────────────┘

         [ 更多历史会话 (Ctrl+L) ]
```

* **快捷键强化**：首屏输入框为空时，按下单键数字 `1` / `2` / `3` 即可直接载入对应历史会话。

## 五、模块四：低配硬件（G2020 等）极限性能压制

与桌面端（Tauri/Chromium）对比指标：

| 关键指标 | 桌面端 (Tauri/WebView) | TUI (2.0.1 目标) | 优势倍数 |
| :--- | :--- | :--- | :--- |
| **常驻内存 (RSS)** | 250MB ~ 400MB+ | **18MB ~ 32MB** | **降低 90% 内存压力** |
| **冷启动耗时** | 1.8s ~ 3.5s | **< 60ms** | **快 30~50 倍** |
| **空闲 CPU 占用** | 1% ~ 3% (Web 渲染管线) | **0.0%** (事件驱动休眠) | 彻底解放双核 CPU |
| **多开体验** | 3 个窗口风扇起飞 | 10 个会话毫无卡顿 | 极端恶劣环境绝对稳定 |
