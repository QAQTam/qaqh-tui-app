## 1. 结论先行

### TUI 运行时

TUI 当前是 **Ringing v2-only**：

- 只有 V2 Fullscreen UI；
- 只有 canonical v2 per-session 单流；
- 没有 v1 SSE 三频道流；
- 没有 v1/v2 双 transport；
- 没有 `--v1` / `--v2-inline` 回退路径；
- 旧入口会明确报错退出。

### 但仓库里仍有三类“旧痕迹”

1. **TUI 内部命名仍是 `seed`**
   - 这是 UI/runtime 内部局部变量和 `SessionState.seed` 的命名债；
   - 不代表 TUI 还有 v1 wire 或双协议；
   - 后端 `session_id` 迁移后，前端调用边界已经使用 `session_id`。

2. **`qaqh-client` 仍导出 v1 形状的兼容别名**
   - `RingingCommand`、`RingingCommandAck`、`TimelineStatus`、`send_command` 等；
   - TUI 调用这些名字，但 client 内部硬切到 v2 typed 路径；
   - 这是 **命名/API 兼容层**，不是 TUI 自己维护的第二套协议实现。

3. **旧脚本和旧文档仍引用 `/ringing/v1/*`**
   - 主要存在于 `scripts/e2e-v2-*.sh` 的测试 setup；
   - 不是 TUI 运行时路径；
   - 如果目标是“全仓严格 v2-only”，应单独清理脚本与文档，不应误判为 TUI 双设计。

## 4. 等待后端裁决的两条主线

### 4.1 Transport

候选：

```text
A. HTTP + SSE（当前）
B. JSON-RPC（over HTTP / WebSocket / stdio）
```

TUI 的偏好：

- **默认继续 HTTP + SSE**；
- HTTP 负责 command / bootstrap / service / content；
- SSE 负责 canonical ordered event stream；
- JSON-RPC 只作为可选 transport adapter；
- TUI 不应直接实现 JSON-RPC transport，必须继续经 `qaqh-client`。

如果后端选择 JSON-RPC，TUI 要求：

1. command/event/cursor/revision/causation 语义不变；
2. `qaqh-client` 增加 transport adapter，TUI 不改业务状态机；
3. 不能引入第二套 command/event 类型；
4. 不能把 WebSocket 重连、去重、游标恢复责任推给 TUI。

### 4.2 Agent loop / context

当前 backend 的事实：

- v1 `MessageStore` 仍是实际模型上下文组装器；
- v2 `ConversationProjection` 还不是 provider-ready context；
- `TurnEngine` 与 `SessionActor/TurnActor` 并存；
- `ContextFlow` 不是真正统一入口；
- role 混用 provider role 与 provenance；
- tool result 恢复有损；
- deferred trailing 回执语义不真实。

TUI 不要求 backend 立即重写，但要求后端先裁决：

1. v2 canonical facts 是否最终接管模型上下文；
2. `SessionActor/TurnActor` 是否成为唯一 turn authority；
3. `ContextPlan / ContextSegment` 是否作为统一 context 模型；
4. v1 `MessageStore` 是迁移输入还是长期第二真源；
5. Team/timeline/conversation 哪个是前端唯一 transcript/roster authority。

## 5. 若裁定 v2 重写 agent 架构：TUI 请求保留/移除

### 必须保留

- canonical session fact log + replay/cursor/reset；
- typed `qaqh-client`；
- per-session 单流；
- command idempotency / causation / receipt；
- driver lease；
- tool ledger、typed tools、sandbox、permission；
- `AgentPath` / canonical graph / mailbox / residency；
- `content_ref` + durable content store；
- provider adapters 留在 gate；
- prefix-cache-first：system 前置、trailing injection、frozen environment。

### 应移除或重做

- `seed` / `session_id` 双身份；
- v1 `MessageStore` 作为模型上下文真源；
- `ContextFlow` 的统一入口假象；
- `TurnEngine` + `SessionActor` 双状态机；
- `system_messages / turns / trailing` 三排序域；
- `source_fact_seq` 作为稳定排序键；
- role 承载 provenance / authority；
- 文本前缀恢复规则；
- ephemeral status 作为 UI 权威；
- child per-seed stream 迫使前端重建 root tree；
- `control.subagents` 与 Team projection 双 roster 源；
- tool snapshot 与 control tools 双快照；
- 不真实 `stored` 回执；
- 死抽象 `LifecyclePolicy`。

## 6. 对“单二进制 + 子命令”的要求

方向：

```text
qaqh
  tui
  webui
  winui
  daemon
  doctor
```

前端要求：

- UI 可以合并进一个二进制；
- transport/state 仍统一走 `qaqh-client`；
- daemon/kernel 仍保有 canonical facts、tool ledger、permission、sandbox 权威；
- UI subcommand 不得直接改 runtime 内部状态；
- 如果走 stdio JSON-RPC，它只是 `qaqh-client` 的 transport adapter；
- WebUI/WinUI/TUI 不能各自复制一份协议实现。
