1. **并行接线期**：已有两位同事并行做前后端接线。**测试失败是并行工作的正常现象**，
   不是"当前改动错了"。判断口径：
   - 失败落在**我本轮改动的文件/断言**上 → 才当回归处理；
   - 失败落在其它文件、或是同事正在改的接线面 → 记录现象，继续推进，不要回滚别人的改动；
   - 门禁命令照跑，但结论要注明"失败点是否属于本轮改动面"。

   （已知基线漂移），但同事也可能在有意更新锁文件。现在的做法是**只在 diff 恰好
   是这条已知升级时才还原**：

   ```bash
   changed=$(git diff --unified=0 -- Cargo.lock | grep -E '^[+-][^+-]' || true)
   printf '%s\n' "$changed" | grep -qvE '^(-version = "2\.0\.1"|\+version = "3\.0\.0"|-checksum = "16b380|\+checksum = "f5dde2|- "itertools 0\.14\.0"|\+ "itertools 0\.15\.0")' \
     || git checkout -- Cargo.lock
   ```

### 1.2 探针（`QAQH_HIT_PROBE`）

- `Off`（默认）只跑几何门禁；`1` 跑完整探针、失败写结构化诊断且**不发布**该帧；
  `strict` 失败直接返回错误（TUI 带诊断退出）。
- 检查：帧身份、几何（空/不可见/越帧/锚点越界/同 z 重叠）、中心+四角可达、
  外扩一格不可达、锚点在真实 buffer 上成立、disabled 不可 dispatch、高 z 覆盖低 z。
- 诊断带齐 spec §8.3 的 12 个字段。
- 一处刻意的语义放宽：被**更高 z** 覆盖时允许该点解析成覆盖层（`ModalRoot` 这类
  整屏阻断层天然被内容盖住）；锁的是"禁止被更低 z / 同 z 抢走"。

## 2. P1：统一按钮与捕获（实现完成）

### 2.1 P1-A：统一按钮模型

新增 `src/ui/v2/button.rs`，实现 spec §5.1 的形状：

```rust
pub enum ButtonState { Idle, Hovered, Pressed, Disabled }
pub struct ButtonVisual { pub state: ButtonState, pub focused: bool }

impl ButtonVisual {
    pub const fn derive(enabled: bool, focused: bool, hovered: bool, pressed: bool) -> Self;
    pub fn surface_style(self, theme: &Theme, focused_bg: Color) -> Style;
    pub fn foreground(self, theme: &Theme) -> Style;
}
```

- 优先级：`Disabled > Pressed > Hovered > Focused > Idle`；
- `pressed` 必须**同时** hovered（拖出立即回常态，松开不提交）；
- `focused_bg` 由调用方给（Workspace 列表 = `chrome.selection`，Modal = `Reset`，
  因为 Modal 用 `▶` 前缀表达焦点），且只在 `Idle` 时生效；
- 无颜色终端（`surface.* == Reset`）退回 `REVERSED`，pressed 额外 `BOLD`；
- disabled 用 `theme.text.dim` 前景，与正常态可区分。

**接线**：三处重复实现全部删除，改走同一份推导。

| 位置 | 之前 | 现在 |
|---|---|---|
| `ui/v2/modal.rs` | 自己的 `ButtonVisual{hovered,pressed}` + `button_style` | `MouseState::visual(target)` → `ButtonVisual::derive` |
| `ui/v2/workspace.rs` | 自己的 `ButtonVisual` + `button_style` + `interactive_row_style` | `workspace_visual(app, target, focused)` + `surface_style` |
| `ui/v2/fullscreen.rs` | `button_style(hovered, pressed, theme)` | back-to-latest 与消息菜单都走 `ButtonVisual` |

一处**有意的视觉归一**：消息菜单"键盘选中但没悬停"的行，从原来的 hover 底色
改成 `theme.chrome.selection`——否则 `Hovered` 与 `Focused` 两档在菜单里完全同色，
优先级表就是摆设。Workspace 列表本来就是这个配色。

`scripts/e2e-subagents-roster.sh` 用私有 fake provider + 隔离 daemon 跑真 PTY：
触发 `spawn_subagent`，确认 roster 出现且 `loaded`，随后在 child 运行期间确认

timeline attach，而 root `TeamSnapshot` 不补发 ephemeral 状态。TUI 现在同时消费
child bootstrap 的 canonical `control.activity`、reliable timeline 的
`TurnOpened` / rebaseline，以及在 owning root 尚未 hydrate 时暂存的 live status
hint；终态 Team 状态不会被这些 hint 复活。roster 身份仍只来自
`TeamSnapshot/TeamDelta`。
