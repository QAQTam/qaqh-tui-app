## 3. 陷阱（给下一个人）

1. **`pkill -f <模式>` 会匹配到你自己**：模式一旦出现在你自己的命令行里，就把自己杀了（实测 exit −1、输出截断、后继命令不执行）。用**显式 PID**，或 `pgrep -af "[c]nb_chat.py"` 括号技巧。
2. **PR 的 base 指向「已合并的分支」时，合并会成功、但改动进不了目标分支**：#25 就这样落在了 `docs/kickoff-drift-2026-09-20` 上，靠查 `betav2` 的 log 才发现（**PR 状态显示 `merged` 会骗人**）。CLI **改不了 base**（`patch-pull` 只认 title/body/state，传 `base` 返回 200 但 base 不动，已用 `-v` 核对）——只能 UI 改，或开补救 PR（#29 的做法）。
3. **监听不会热重载**：改完 `cnb_chat.py` 必须重启 `watch`，否则跑的还是旧代码（本轮踩过）。重启用 `setsid nohup … < /dev/null >> log 2>&1 &`，并**保持同一份 state 目录**（游标在里面；换目录＝重放全部历史）。主工作树里那份 `cnb_chat.py` 是**未跟踪副本**（`main` 没有这个工具）。
4. **`main` 工作树里的 `cnb-chat/` 会挡住将来的 `betav2`→`main` 合并**：`main` 目前没有这个工具（只在 `betav2`），所以那份是未跟踪副本；合并时 git 会拒绝覆盖（`untracked working tree file would be overwritten`）。**先删副本再合**。
5. **NPC reviewer 会给自相矛盾的复评**（同一次 #23 上：17:32 说「新增 1 项阻断」、17:33 说「没有新发现阻断项」）。**逐条复现再采信**——本轮它两条里一条真（「删+加且计数不变」的静默漏，已修）、一条假（`fetch_issues` 没翻页；实测翻页正常）。

### 6.1 现象与定位

`main`（`4b1fb59`）运行 TUI：

```
thread 'main' (445191) panicked at src/app/render/seg.rs:221:17
窗口内出现未渲染的估算块（虚拟化不变式被破坏）
```

**已精确复现**（临时测试，跑完已还原，工作树仍 0 改动）：

```
PROBE top_render=0  total_after=700  top_window=670
panicked at src/app/render/seg.rs:221:17
```

### 6.2 根因：`top` 算了**两遍**，两遍用的是**不同的 total**

| 步骤 | 位置 | total 来源 | 干什么 |
|---|---|---|---|
| ① 渲染 | `App::ensure_render_caches`（`src/app/mod.rs:1871-1879`） | **refresh 之前**的 `cache.total_lines()` | 决定渲染哪一段 |
| ② 取窗口 | `ui/transcript.rs:32-35` | **refresh 之后**的 `bc.total_lines()` | 决定 `window(top, height)` |

`src/ui/mod.rs:129-130` 的注释声称「共用一份避免滚动位置错位」——**几何一旦漂移，这份就没共用成**。

首帧（默认 `follow=true`）的数值链：缓存为空 → `total=0` → `top_render=0` → refresh 只渲**顶部**；
refresh 过程中 `total` 涨到 700（真值 647，**+53 漂移**）→ `draw` 重算出 `top_window=670` →
去取**底部**窗口 → 那些块从未渲染 → 撞 `debug_assert`。

### 6.3 两个必须带走的判断

1. **release 下不崩，但更糟。** `debug_assert` 被编译掉后走到 `skip = 0; continue`，该段不产出任何行。
   实测 **请求 30 行、取到 0 行 —— 整个视口静默变空**。直接违反 B1「丢弃必须可见」，比崩溃更难发现。
2. **W-09 修了不够。** 复现就是在当前 `betav2`（`ed34878`）上跑的 → **W-11（首帧估算偏离 +53 行）
   是当前唯一在册的触发源**；`main` 上则是 W-09 + W-11 两个源都在。

触发门槛：会话够长（底部落在 `KEEP_MARGIN_TURNS`=8 回合之外）+ 有 markdown 代码块或工具卡 + 默认 follow
→ **首帧即触发，不需要滚动**。
