## 0. 背景

旧版 ask_user 把选项显示为 `[0] [1] [2]...`，但按键 `1` 实际选择第一项
（0-based 内部下标）。用户看到的编号与操作编号不一致，长问题还会把多个问题
挤在一个 Modal 中，导致正文、选项和输入区互相争抢空间。

---

## 1. 设计结论

v2 ask_user 采用 Grok 风格的阻塞式单题分页：

- 一页只显示一个问题；
- 问题正文完整换行，长文本通过 PgUp/PgDn 滚动；
- 左右键切换问题，不把所有问题堆在一个 Modal 中；
- 选项快捷键统一为 1-based：`1..9`、`a..f`；
- 选项光标与选中状态分离，避免“移动光标即提交”；
- 自定义输入是当前问题的最后一行，使用 `e` / `z` 进入。

---

## 2. 键位

| 按键 | 行为 |
|---|---|
| `←` / `→` | 上一题 / 下一题，边界处不循环 |
| `↑` / `↓` / `j` / `k` | 移动当前题选项光标 |
| `Home` / `g` | 跳到当前题第一个选项 |
| `End` / `G` | 跳到当前题最后一行（含自定义行） |
| `Enter` | 选择当前行；非最后一题自动前进，最后一题提交 |
| `Space` | 只选择当前行，不前进 |
| `1..9` | 直接选择前 9 个选项 |
| `a..f` | 直接选择第 10..15 个选项 |
| `e` / `z` | 进入当前题自定义输入 |
| `PgUp` / `PgDn` | 滚动长问题正文 |
| `Esc` | 跳过并中止当前 ask 回合 |

在自定义输入态：

- `Enter` 提交当前答案；非最后一题前进，最后一题提交整个 ask；
- `Esc` 取消输入，保留原有选择；
- 控制字符不进入输入缓冲。

---

## 3. 提交规则

- 每个问题必须有预设选择或非空自定义答案；
- 提交失败时定位到第一个未答问题，并显示错误；
- 自定义答案优先于旧预设选择；选择新预设项时清除该题自定义草稿；
- 最后一题 `Enter` 后统一调用既有 `InteractionAskRespond`，不新增协议；
- `Esc` 继续调用既有 `InteractionAskDismiss`，行为与 v1 语义一致。

---

## 4. 视觉与布局

```text
╭─ ❓ 问题 2/3 · batch ─────────────────────────────╮
│  第二题：请选择完整方案                           │
│                                                   │
│  ▶ 1 ○ 方案一                                     │
│    2 ◉ 方案二                                     │
│    3 ○ 方案三                                     │
│    z ○ 自定义输入                                 │
│                                                   │
│ ←→ 切换问题 · ↑↓ 选择选项 · Enter/Space 选择       │
╰───────────────────────────────────────────────────╯
```

- 标题显示当前页和总题数；
- 选中项使用 accent 与 `◉`，光标使用 `▶`；
- 长问题先完整换行，不截断正文；
- 自定义行固定位于选项之后；
- 错误信息显示在当前问题下方。

---

## 5. 验收

- [x] 屏幕编号与按键编号一致，均为 1-based；
- [x] 一页只显示一个问题；
- [x] 左右键切换问题；
- [x] 数字键 `2` 选择第二个选项并前进；
- [x] Enter 在最后一题提交完整答案；
- [x] 自定义行可进入编辑态；
- [x] 未答提交会回到第一个缺失问题；
- [x] v2 Agent draw 会优先绘制 pending ask Modal；
- [x] 不改 qaqh.Ringing 协议。
