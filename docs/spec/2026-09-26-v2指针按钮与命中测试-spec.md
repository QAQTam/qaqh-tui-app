## 0. 一句话

所有鼠标交互必须由**每帧生成的单一 HitMap**决定；绘制、命中、hover、pressed、
滚动与测试共用同一份几何。命中只能针对用户已经看到的帧，严格探针一旦发现不一致
必须失败，不能降级成“大多数时候能点到”。

---

## 1. 目标与非目标

### 1.1 目标

1. **键盘优先，鼠标增强**：任何鼠标可完成的操作都必须有键盘路径。
2. **单一坐标系**：全仓只使用一套权威终端坐标系，禁止组件各自维护偏移。
3. **绘制与命中同源**：按钮画在哪里，命中区就在哪里，不能由两套公式分别计算。
4. **帧绑定**：鼠标事件只对 `presented frame` 的 HitMap 生效。
5. **状态明确**：hover、pressed、release、取消、禁用、键盘焦点必须可区分。
6. **不可见即不可点**：被裁剪、遮挡、滚出视口或已失效的目标不能被命中。
7. **严格可验证**：中心、四角、外扩、遮挡、resize、路由切换均有自动化证据。
8. **故障探针可证伪**：探针自身必须有反例测试，不能永远返回通过。

### 1.2 非目标

- 不新增视觉主题或改变现有 token 体系。
- 不引入后端协议或 daemon 契约变更。
- 不要求所有弹窗、列表和文本区域一次性支持鼠标。
- 不实现双击、三击、右键拖拽等未定义的复杂手势。
- 不追求所有终端行为完全一致；以兼容矩阵定义可接受边界。
- 不把鼠标变成主交互路径，键盘始终是可完成全部流程的基线。

## 2. 术语

### 2.1 权威坐标

本仓以 ratatui `Rect` 为唯一权威几何：

```rust
pub struct Rect {
    pub x: u16,
    pub y: u16,
    pub width: u16,
    pub height: u16,
}
```

约束：

- `x` / `y` 从 0 开始；
- 区间为半开区间：`[x, x + width)`、`[y, y + height)`；
- `width == 0` 或 `height == 0` 表示空矩形；
- 只有终端输入适配层可以把终端事件坐标转换成该坐标系；
- App 状态只保存语义目标，不保存屏幕坐标。

禁止：

- 在组件内部混用 1-based 与 0-based 坐标；
- 用 `left/right/top/bottom` 闭区间表示新接口；
- 在事件处理时重新推导另一套按钮位置；
- 在 App 层保存 `column/row` 作为持久状态。

### 2.2 指针对象

| 名称 | 含义 |
|---|---|
| `PointerTarget` | 语义目标，如按钮、列表行、滚动条、消息块 |
| `HitRegion` | `Rect + PointerTarget + button + enabled + z` |
| `HitMap` | 某一帧、某一路由下的全部可见命中区 |
| `FrameId` | 绘制序号；每次真正提交一帧后递增 |
| `PresentedFrame` | 已经绘制完成、用户可见的帧 |
| `Probe` | 用固定点反查 HitMap，验证可达性与视觉一致性 |
| `Anchor` | HitRegion 与渲染字形之间的视觉锚点 |

## 3. 架构约束

### 3.1 单向数据流

```text
App state
  -> ScreenRoute
  -> draw(frame)
  -> FrameHitMap { frame_id, route, regions }
  -> terminal flush
  -> last_presented_frame = FrameHitMap
  -> pointer event
  -> last_presented_frame.resolve(column, row)
  -> PointerTarget
  -> dispatch to existing semantic action
```

任何一环都不能绕过这个顺序。

### 3.2 HitMap 必须由绘制过程生成

推荐接口：

```rust
pub struct FrameHitMap {
    pub frame_id: u64,
    pub route: ScreenRoute,
    pub regions: Vec<HitRegion>,
}

pub struct HitRegion {
    pub rect: Rect,
    pub target: PointerTarget,
    pub button: MouseButton,
    pub enabled: bool,
    pub z: u16,
}
```

要求：

- 绘制按钮、列表行、滚动条时同时登记 `HitRegion`；
- 不允许绘制完成后再由另一份布局函数补登记；
- 不允许事件到达时重新运行整套布局来猜目标；
- HitMap 随帧整体替换，不增量修改旧帧。

### 3.3 事件必须绑定 presented frame

鼠标事件到达时：

- 如果存在 `last_presented_frame`，使用它的 `frame_id`、`route` 和 HitMap；
- 如果该帧已因 resize、路由切换或强制重绘失效，则丢弃事件或等待下一帧；
- 不允许把当前 `App` 状态和旧 HitMap 混用；
- 批量消息处理期间发生路由变化时，后续鼠标事件必须重新绑定最新 presented frame。

最低验收：

- resize 后旧坐标不能命中；
- Modal 关闭后旧按钮不能命中；
- Workspace 切页后旧行目标不能命中；
- 滚动后旧的可见行坐标不能命中新内容。

### 3.4 z-order 与裁剪

优先级由显式 `z` 决定，禁止依赖 Rust `match` 的书写顺序隐式决定跨组件层级。

建议层级：

```text
Modal root          z = 300
Modal content       z = 310
Modal button        z = 320
Workspace footer    z = 200
Workspace row       z = 100
Agent overlay       z = 50
Agent body          z = 0
```

规则：

- 同一点命中多个区域时，取最高 `z`；
- 同 `z` 重叠视为规范错误，strict probe 必须报错；
- HitRegion 必须先与自身 clip rect 相交；
- 被遮挡区域可以保留用于诊断，但不能被 dispatch；
- Modal root 必须阻断底层所有鼠标事件，禁止 click-through。

## 4. 指针状态机

### 4.1 事件

至少支持：

```text
Moved
Down(Left)
Up(Left)
Drag
ScrollUp
ScrollDown
Leave
RouteChanged
Resized
FocusLost
```

### 4.2 状态

```text
Idle
  -> Hovered
  -> Pressed
  -> ReleasedInside
  -> Cancelled

Disabled
  -> 不进入 Pressed
```

规则：

- `Moved` 只更新 hover，不触发动作；
- `Down` 只进入 pressed，不触发动作；
- `Up` 只有 released target 与 pressed target 相同才触发动作；
- 按下后移出目标只取消视觉，不提交；
- 移回原目标并松开可以提交；
- 路由切换、resize、Modal 关闭、Workspace 切页必须清空 hover/pressed；
- 禁用目标不能进入 pressed；
- hover/pressed 不得泄漏到下一帧或下一路由；
- 键盘 focus 与鼠标 hover 分开表达，互不覆盖。

### 4.3 指针捕获

以下交互需要 pointer capture：

- 滚动条 thumb 拖动；
- 未来可能出现的滑杆、范围选择、文本选择；
- 拖动开始后，后续 motion 仍路由给同一拖动会话。

捕获规则：

- 捕获期间忽略其它 hover 目标；
- 捕获结束条件为 `Up`、`Leave` 或显式取消；
- resize 导致几何失效时必须取消捕获；
- 捕获必须保存 `grab_offset`，不能每次 motion 都重新以指针中心对齐。

## 5. 按钮规范

### 5.1 单一按钮模型

全仓只保留一套按钮状态与样式推导：

```rust
pub enum ButtonState {
    Idle,
    Hovered,
    Pressed,
    Disabled,
}

pub struct ButtonVisual {
    pub state: ButtonState,
    pub focused: bool,
}
```

禁止每个页面分别定义自己的 `hovered/pressed` 推导和颜色规则。

### 5.2 视觉优先级

```text
Disabled > Pressed > Hovered > Focused > Idle
```

要求：

- pressed 必须同时满足 hovered 与 pressed target 相同；
- 禁用态必须与正常态可区分；
- hover 必须整块生效，不能只改文字颜色；
- 无颜色终端使用 `REVERSED`；
- pressed 在无颜色终端额外使用 `BOLD`；
- 颜色只能来自 theme token。

### 5.3 点击语义

- 默认采用 press-release-inside；
- 列表行可使用 Down 即选中，但必须在规范中明确；
- 右键菜单只能在 Down 时打开，不能在 Up 时二次触发；
- 滚动条点击与拖动必须走独立状态机，不能伪装成按钮；
- 鼠标动作必须复用键盘动作的语义入口，不能复制业务逻辑。

### 5.4 布局与降级

- 按钮宽度必须按 Unicode 显示宽度计算；
- 按钮不能写满终端最后一列，避免自动折行；
- 终端过窄时按明确顺序降级：丢 hint、缩短 label、减少按钮、最后不绘制；
- 只要按钮不可见，就不能登记可点击区域；
- 绘制与命中必须调用同一个按钮布局函数；
- 按钮视觉锚点必须能定位到确定字形或确定单元格样式。

## 6. 滚动条与拖动

滚动条必须复用同一份 `ScrollbarMetrics`：

```rust
pub struct ScrollbarMetrics {
    pub track: Rect,
    pub thumb: Rect,
    pub max_offset: usize,
    pub viewport_height: usize,
}
```

规则：

- thumb 高度按 `viewport / total` 计算；
- `offset = 0` 时 thumb 贴底并继续 follow；
- `offset = max` 时 thumb 贴顶；
- 点击轨道把 thumb 中心移动到点击位置；
- 拖动保存 `grab_offset`，用绝对坐标映射；
- 拖动和滚轮、PageUp/PageDown 最终走同一个 scroll state；
- 无内容可滚时不登记滚动条 HitRegion；
- resize 后重新计算 metrics，旧拖动会话作废。

## 7. 鼠标捕获策略

鼠标捕获必须有唯一所有者，通常是 terminal host。

推荐策略：V2 Fullscreen 进入 alternate screen 后统一启用 mouse capture，
退出、pager、suspend、启动失败时恢复；原生选择通过 `Shift` 继续可用。
如果未来改为“仅交互页按需捕获”，必须全仓切换策略并同步测试，不能一个路由按开启、
另一个路由按关闭实现。

规则：

- 进入捕获和退出捕获必须成对；
- panic、pager、suspend、启动失败路径都必须恢复终端；
- 不允许一个入口全局开启、另一个入口假设未开启；
- 捕获开启时必须提供终端原生选择的替代说明，例如 `Shift` 选择；
- 捕获关闭时，鼠标滚轮、hover、点击能力不得默默承诺；
- 无论采用哪种策略，键盘路径必须完整可用。

测试至少覆盖：

- 启动成功后 capture 状态符合策略；
- 退出后 capture 已关闭；
- pager 暂停后恢复；
- 异常路径不会遗留 mouse mode；
- 原始字节流中的 enable / disable 序列成对。

## 8. 故障探针

### 8.1 环境开关

```text
QAQH_HIT_PROBE=1        # 每帧自检，失败写诊断
QAQH_HIT_PROBE=strict   # 失败直接返回错误或 panic
```

默认关闭；CI、PTY 测试和故障排查使用 strict。

### 8.2 每帧检查

对每个可见 HitRegion 检查：

1. 中心点命中自己；
2. 四角命中自己；
3. 外扩一格不命中自己；
4. rect 与 clip rect 的交集非空；
5. rect 完全落在可见帧内；
6. 视觉锚点存在且与目标一致；
7. disabled 目标不可 dispatch；
8. 被更高 z 覆盖的目标不可 dispatch；
9. route 与 frame_id 匹配；
10. HitMap 不包含已经滚出视口或已关闭页面的目标。

### 8.3 诊断输出

失败输出必须包含：

```text
frame_id
route
target
screen rect
local rect
z
button
probe point
expected target
actual target
terminal size
scroll offset
```

没有这些字段的报错不足以定位 XY 类问题。

### 8.4 探针元测试

探针本身必须有反例测试。至少注入：

- HitRegion 向右偏 1 列；
- HitRegion 向下偏 1 行；
- 删除视觉锚点；
- 两个同 z 区域重叠；
- 高 z 区域覆盖低 z 区域但优先级未生效；
- 路由切换后保留旧 HitMap；
- resize 后继续使用旧 rect；
- disabled 目标仍可 dispatch；
- 点击外层 Modal 穿透到底层 Workspace。

这些测试必须全部失败。若探针不失败，说明探针无效。

## 9. 测试分层

### 9.1 几何单测

- `Rect::contains` 的四条边和四个角；
- 空矩形；
- 饱和加减；
- 局部坐标与屏幕坐标往返转换；
- clip 后矩形；
- 多级嵌套布局的转换；
- CJK / emoji 对文本布局的影响不改变 cell 矩形语义。

### 9.2 状态机单测

- hover 不触发；
- Down 不触发；
- Up-inside 触发一次；
- Up-outside 不触发；
- 拖出再拖回可触发；
- route/resize 清空状态；
- disabled 不进入 pressed；
- 滚动条捕获跨出轨道仍有效；
- Up 后捕获释放。

### 9.3 渲染与 HitMap 一致性

使用 `TestBackend` 对每种页面和尺寸检查：

- 绘制后生成的 HitMap；
- 按钮、行、滚动条的视觉锚点；
- 中心、四角、外扩；
- 遮挡和裁剪；
- 无颜色主题的反显降级；
- 窄终端降级后不产生幽灵 HitRegion。

推荐尺寸矩阵：

```text
40x12
60x14
80x24
100x30
120x30
160x40
```

### 9.4 PTY 集成测试

必须覆盖真实终端字节链路：

- SGR 鼠标按下、抬起、移动、滚轮；
- 序列跨 chunk 切断；
- 多事件合批；
- 路由切换前后；
- resize 前后；
- 滚动后点击；
- 拖动滚动条跨出轨道；
- Modal 打开、关闭、确认；
- 列表页选择、进入、返回。

测试坐标应从实际渲染结果或共享布局 helper 推导，避免在测试里复制一套硬编码公式。
如果测试必须 pin 公式，必须同时有探针验证实际渲染位置。

### 9.5 端到端行为测试

鼠标测试不能只断言“界面有反馈”，还要断言业务结果：

- 点击 ask 选项后，后端或 provider 收到的是被点选项；
- 点击 permission 后，决策真的到达对应语义入口；
- 点击 Workspace 行后，路由和选中项正确变化；
- 点击取消后，不产生提交副作用；
- 禁用按钮点击后，没有状态变化。

### 9.6 随机与压力测试

对固定 seed 的随机事件序列检查：

- 不 panic；
- 不残留 pressed/capture；
- 不命中已关闭页面；
- 不 click-through；
- 不出现越界 rect；
- 同一事件序列可复现。

## 10. 验收门槛

一项鼠标/按钮实现只有同时满足以下条件才算完成：

- `cargo fmt --all -- --check` 通过；
- `cargo clippy --all-targets -- -D warnings` 通过；
- 单元测试、集成测试、PTY 测试通过；
- `QAQH_HIT_PROBE=strict` 在覆盖场景中零失败；
- 所有可见交互目标中心与四角可达；
- 外扩一格不可达；
- 被裁剪、遮挡、禁用目标不可 dispatch；
- resize、路由切换、滚动后无 stale hit；
- capture enable / disable 成对；
- 探针反例测试能够稳定失败；
- 键盘路径与鼠标路径产生同一业务结果。

任何一项失败都不能以“终端差异”“偶发”“手测可点”为由跳过。

## 11. 实施顺序

### P0：命中基础设施

- 定义 `PointerTarget`、`HitRegion`、`HitMap`、`FrameId`；
- 绘制阶段生成 HitMap；
- 鼠标只对 last presented frame 命中；
- 统一 hover / pressed 清理；
- 增加 `QAQH_HIT_PROBE=strict`；
- 为探针写反例测试。

### P1：统一按钮与捕获

- 抽出统一 `ButtonState` / `ButtonVisual`；
- Modal、Workspace、Agent 共用样式与状态推导；
- 明确 capture 策略并补齐进入/退出测试；
- 增加无颜色、窄终端、disabled 测试。

### P2：滚动条与拖动

- 抽出共享 `ScrollbarMetrics`；
- 实现轨道点击、thumb 拖动、grab offset；
- 覆盖 resize、跨轨道拖动、滚轮与键盘同状态；
- 将滚动条纳入 strict probe。

### P3：扩展交互

- 工具卡点击展开；
- thinking 历史展开；
- 消息菜单与更多消息入口；
- 文本选择、复制和搜索；
- 每个新增目标必须复用 HitMap 与探针，不得另开坐标路径。

---

## 12. 反模式

以下做法禁止进入实现：

- 渲染用一套坐标，hit-test 用另一套；
- App 状态保存屏幕坐标；
- 测试只测中心点；
- 只测“能点”，不测四角、外扩、遮挡；
- 测试复制页面布局公式而不验证实际画面；
- hover 改变点击目标；
- Down 和 Up 分别触发两次动作；
- route 切换后保留 hover/pressed；
- resize 后继续使用旧 HitMap；
- Modal 点击穿透到底层；
- 滚动条只画不参与命中，却暗示可拖动；
- 探针只检查自己生成的 HitMap，不检查渲染画面；
- 探针没有反例测试；
- 以手测通过替代自动化证据。
