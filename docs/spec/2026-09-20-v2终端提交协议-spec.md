---

## 0. 一句话

v2 把**已封口内容一次性提交到终端 scrollback**，把**可变内容留在 inline live viewport**；
提交由稳定 `commit_id` 和 ledger 保证幂等，历史重放、重连、resize 都不允许重复输出。

---

## 1. 终端模型

### 1.1 区域

```text
┌──────────────────────────────────────────────┐
│ terminal scrollback                          │
│   committed user / assistant / tool / system │
│   append-only, terminal-owned scroll         │
├──────────────────────────────────────────────┤
│ inline viewport                              │
│   live block                                 │
│   composer                                   │
│   activity / status / shortcuts              │
└──────────────────────────────────────────────┘
```

- scrollback 由终端拥有，App 不读取、不重绘、不计算总高度。
- inline viewport 由 ratatui `Viewport::Inline` 拥有，App 每帧重绘。
- 复杂管理面临时切 alternate screen，退出后恢复 inline viewport。

### 1.2 生命周期

```text
startup
  -> enter raw mode
  -> init inline viewport (height H)
  -> render live viewport
  -> commit sealed blocks
  -> resize / session switch / theme switch
  -> exit: restore terminal, leave scrollback intact
```

启动时不清空 scrollback；退出时保留 scrollback。

---

## 2. 块状态机

每个可提交块必须经过以下状态：

```text
Live -> Sealed -> Committed
          \-> Discarded (仅非用户可见的内部块)
```

| 状态 | 位置 | 可变 | 说明 |
|---|---|---|---|
| `Live` | inline viewport | 是 | 流式 assistant / tool / thinking |
| `Sealed` | 内存 | 否 | 内容冻结，生成 ANSI 行 |
| `Committed` | terminal scrollback | 否 | 已 emit，ledger 有记录 |
| `Discarded` | 无 | 否 | 不进入 UI 的内部块 |

规则：

- `Live` 块不得直接写入 stdout。
- `Sealed` 后不得再修改内容；若上游重放，按 `commit_id` 幂等。
- `Committed` 后不得重绘、重染、重排。
- 任何丢弃/折叠/截断必须在 `Sealed` 时确定并可见（B1）。

## 3. Commit Ledger

### 3.1 目的

防止以下路径重复输出：

- SSE 重连；
- timeline re-baseline；
- epoch 变化；
- 会话重新 attach；
- 手动 refresh；
- resize 后的历史重放；
- 用户切换主题后的重放。

### 3.2 数据结构

```rust
pub struct CommitId {
    pub seed: String,
    pub turn_id: String,
    pub block_id: String,
    pub revision: u64,
}

pub struct CommitLedger {
    committed: HashMap<CommitId, CommitRecord>,
    order: Vec<CommitId>,
}

pub struct CommitRecord {
    pub committed_at: Instant,
    pub ansi_len: usize,
    pub content_hash: u64,
}
```

### 3.3 幂等规则

- `commit_id` 相同且 `content_hash` 相同：跳过。
- `commit_id` 相同但 `content_hash` 不同：视为冲突，记录诊断，不重复 emit。
- `commit_id` 不存在：允许 emit。
- ledger 按会话维护；切会话时可持久化到内存或磁盘缓存。
- 进程退出后 scrollback 已存在，ledger 可随进程结束；重新启动不重放旧历史。

## 4. Inline Viewport

### 4.1 内容

inline viewport 只承载：

- 当前 `Live` assistant / tool / thinking；
- composer；
- activity line；
- status / shortcuts；
- 临时 bottom panel（快速确认）。

### 4.2 高度

- 最小高度：composer 3 行 + status 1 行 + shortcuts 1 行。
- 最大高度：不超过终端高度的 60%。
- live block 高度超过上限时，viewport 内使用尾窗/折叠，不写入 scrollback。
- 窄终端优先保 composer 与正文，隐藏 shortcuts、status 次要字段。

### 4.3 重绘

- `Live` 内容变化时只重绘 inline viewport。
- `Committed` 内容变化不触发重绘。
- 动画只在 viewport 内覆盖 cell，不进入 scrollback。
- 无变化帧允许跳过 draw。

---

## 5. 提交时机

| 事件 | 提交内容 |
|---|---|
| `TurnOpened` | 用户 prompt |
| `TurnSealed` | assistant 最终消息、回合分隔 |
| `BlockSealed` | 已封口 text / tool / notice |
| `ToolCompleted` | 工具卡最终态 |
| `ThinkingSealed` | thinking 聚合行 |
| `SystemEvent` | 系统提示、错误、reset |
| `InteractionResolved` | 权限/ask/plan 结果摘要 |

提交顺序必须与 timeline 顺序一致；不得先提交后到的旧块。

## 6. Resize 协议

终端 resize 分两类：

### 6.1 宽度不变，高度变化

- 调整 inline viewport 高度；
- 不重放 scrollback；
- live block 重新折行。

### 6.2 宽度变化

终端会在 SIGWINCH 前自行 reflow，行为不一致。策略：

1. 检测宽度变化；
2. 清屏 + 清 scrollback（`ESC[2J ESC[3J ESC[H`）；
3. 从完整历史模型重放已提交块；
4. 重建 inline viewport；
5. 重放失败或历史不完整时，标注「历史在 resize 后可能不完整」。

要求：

- 重放必须走 commit ledger，禁止重复。
- 历史模型不完整时不得伪造内容。
- resize 重放纳入性能基准。

## 7. 会话切换

采用 D2：单活动会话 + 工作区切换。

### 7.1 切换到后台会话

- 当前会话的 `Live` 块 seal + commit；
- 保存 ledger 与滚动历史模型；
- 清空 inline viewport。

### 7.2 切换到前台会话

- 清屏 + 清 scrollback；
- 按 ledger 顺序重放该会话已提交块；
- 重建 inline viewport；
- 恢复该会话的 live 状态。

### 7.3 不完整历史

若会话被 offload / 截断：

- 重放可见部分；
- 在开头显示「更早历史不可用」；
- 不伪造、不静默丢失。

---

## 8. 主题切换

已提交 ANSI 颜色不可变。策略：

- 默认：主题切换只影响 inline viewport 与后续内容；
- 可选：用户确认后清屏 + 重放历史，使旧历史套用新主题；
- 重放必须幂等；
- `Terminal` 主题不写背景色，天然不受影响。

---

## 9. 重连 / re-baseline

- 收到 reset / gap / epoch 变化时，先冻结当前 live 块；
- 重新拉取 timeline；
- 按 `commit_id` 过滤已提交块；
- 只提交新增块；
- 若无法判定重复，优先不重复输出，并在诊断中记录。

---

## 10. Offload / 分页 / 截断

- offload 后只保留预览壳：已提交 scrollback 不受影响；
- resize / 切会话需要重放时，offload 内容不可重放，必须如实标注；
- `has_more` / 加载更早：在 Agent View 中不插入 scrollback 顶部，改为 Workspace View 浏览；
- B1：所有不可重放内容必须有可见标注。

---

## 11. 鼠标与选择

- 默认不捕获鼠标，优先保终端原生选择/复制/滚轮；
- 需要鼠标交互时进入显式 mouse mode；
- mouse mode 下提示用户 `Shift` 选择或提供退出；
- 快捷键始终可用，不依赖鼠标。

---

## 12. 错误处理

- emit 失败：保留 `Sealed` 状态，下一次重试；
- 部分写入：记录字节偏移，避免重复/截断；
- 终端不支持 inline viewport：降级 fullscreen v1，并提示；
- `NO_COLOR`：只影响颜色，不影响提交协议；
- panic / crash：恢复终端，保留已提交 scrollback。

## 13. 测试与验收

### 13.1 单元

- `commit_id` 幂等；
- ledger 冲突处理；
- ANSI 渲染稳定性；
- 状态机非法迁移拒绝。

### 13.2 集成

- 真实 PTY + daemon：发送、流式、工具、权限、ask、plan；
- 重连/re-baseline 不重复；
- resize 宽度变化重放；
- 会话切换重放；
- 主题切换行为；
- 退出后 scrollback 保留。

### 13.3 终端矩阵

- Windows Terminal / PowerShell
- WezTerm
- iTerm2
- Alacritty
- Kitty
- GNOME Terminal / Konsole
- tmux / SSH

每项记录：scrollback、inline viewport、resize、truecolor、鼠标、复制。

### 13.4 证伪

每个关键锁必须写明「故意破坏会变红」的方式，例如：

- 删除 ledger 去重 → 重连用例必须重复输出；
- 允许 `Committed` 重绘 → 历史稳定性快照必须失败；
- resize 不清 scrollback → 兼容矩阵必须出现错位/重复。
