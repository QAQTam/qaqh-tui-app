## 0. 一句话

把渲染粒度从「回合」降到「块」、把动画从缓存里赶出去、把流式成本从 O(全文) 压到 O(尾行)；思考链路改为 **ActivityBar 单行活动区 + Ctrl+T 浮层 + 按需回放**，历史思考在渲染层废弃（聚合计数进回合头）；工具留在 chat 流内按运行组折叠、视口外卸载；数据面对齐 09-18 跨仓契约 v1，前端删除全部 JSON 考古代码。

## 1. 问题定位（为什么渐进修补不够）

### 1.1 性能：活动回合 = 每帧 O(回合)

- `turn_cache_key` 只要回合内任一块 animating 就把 `frame_now()` 混进键（`render_transcript.rs:437-458`）→ 流式期间**每 200ms 整回合重渲**；每个 delta bump `rev` 同样触发。
- 整回合重渲的账单：sealed markdown 块重跑 pulldown+syntect；全部 reasoning 重跑 O(text) 句子切分（`render_transcript.rs:181-212`）；工具卡重跑 3~4 次 `serde_json::from_str`。
- 每条 SSE 消息一帧、无脏检查（`main.rs:128-151`），Tick 每 200ms 必绘（`main.rs:113`）。
- 段粒度是回合（`session.rs:462-477`），多工具 + 长思考把单个回合撑到上千行——**粒度与变更频率错配**，这是架构问题，调参数救不了。

### 1.2 密度：思考链路 + 工具卡淹没正文

- `show_reasoning` 默认 `true`（`app/mod.rs:598`），思考全文渲染。实测 110 回合 = 124,690 行（`session.rs:407` 注释）。
- 工具卡逐卡独立：BlockTool 2 行头 + args + diff(≤60 行) + 输出(8/24 行) + footer；2500 次工具调用的会话 → transcript 是不可导航的墙。
- 现有折叠手段（`is_default_expanded`、F7、24 行帽）是逐卡打补丁，缺一个「批量」维度的控制。

### 1.3 数据：展示契约缺失放大 1.1/1.2

summary 86.4% 是被 512 截断的 JSON（U-10 实测），前端 8 个补偿函数 + 全仓 8 处 `serde_json::from_str`，且**每次重渲重复解析**。

### 1.4 维护：`render_transcript.rs` 4119 行单文件

缓存维护、reasoning normalize、工具卡、diff 渲染、500 行测试混在一个文件，任何改动都在同一冲突面上。

## 2. 设计原则

1. **内容只算一次**：渲染结果按 `(身份, rev, 宽度, 展开态)` 缓存，与帧无关。
2. **动画永不进缓存**：墙钟字形走槽位覆盖，不触发任何 rebuild。
3. **渲染粒度 = 变更粒度**：delta 打到哪一块，就只重渲哪一块。
4. **密度自适应**：历史自动折叠、运行态瘦身、焦点展开；丢弃必须可见（B1）。

### 3.2 BlockSeg 二级缓存（核心数据结构）

```rust
pub struct BlockSeg {
    /// (block_id, rev, block_state, width, 展开态, ToolView 分派) 的 FNV——**不含帧号**
    key: u64,
    /// 精确渲染结果 或 估算高度（虚拟化语义沿用）
    body: BlockBody,               // Lines(Arc<[RenderLine]>) | Height(usize)
    /// 动画槽位（随 body 一起失效/淘汰），见 3.3
    anim: SmallVec<AnimSlot>,
    /// 解析一次的视图数据（JSON 考古的落脚点，U-10 落地后整体删除）
    data: Option<ToolViewData>,
}

pub struct TurnSeg {
    turn_id: String,
    /// 回合结构键：块数 / 顺序 / 回合态 / sealed / offloaded——不含块内容
    struct_key: u64,
    blocks: Vec<BlockSeg>,         // 含头/尾装饰块，与 round.blocks 同序
}

pub struct TranscriptCache {      // 取代 SegmentCache
    width: u16, show_reasoning: bool,
    banner: Option<BlockSeg>, empty: Option<BlockSeg>,
    turns: Vec<TurnSeg>,
    stats: Stats,                  // rebuilt_blocks / resident_blocks / layout_passes
}
```

- 块级 miss 才重渲；回合新增/丢头仍走 `turn_id` 对齐复用（沿用现逻辑，`render_transcript.rs:620-661`）。
- 虚拟化不变式原样保留：视口 ± KEEP_MARGIN 覆盖到的块必须持有 Lines（`window_never_contains_unrendered_segments` 语义原样迁移）。
- 宽度变化仍走 ratio 高度缩放 + 丢 Lines（`render_transcript.rs:583-603` 的策略，作用于块粒度）。
- **键显式含 `block_state`**（reviewer §四.5）：Open→Sealed 会从纯文本切 markdown 路径，不得依赖「可见变更必 bump rev」的口头约定；`show_reasoning` / 宽度变化维持 cache 级整体失效。

### 3.3 动画出带（AnimSlot）

```rust
pub enum AnimKind { Spinner, Cursor, Thinking, ProgressIndeterminate }
// r4：Thinking = 思考流式头标四帧圆环（原 render_transcript 内联墙钟帧序收编为
// thinking_glyph(frame_now())，语义不变）；M2 思考退出 transcript 后随管线删除。
// ProgressIndeterminate 暂无生产者（info 行 bar 每帧独立渲染不入缓存，且多 cell
// 区域无法用单 cell 槽位表达），draw 期跳过。
pub struct AnimSlot { row: u16, col: u16, kind: AnimKind }   // 段内坐标
```

- 缓存行里**不写**动画字形；draw 阶段在 `Paragraph` 之后用 `frame.buffer_mut()` 对可见槽位覆盖 cell。
- **槽位安全（修订）**：槽位所在列必须在折行阶段**预留占位空格**，draw 只覆盖这些占位
  cell；禁止对可能正压在宽字符（CJK）上的 cell 做单 cell 覆盖（会把宽字符切裂）。
- 槽位坐标是段内 `(row, col)`：draw 前必须按当前窗口 offset 平移并裁剪到 widget rect，
  半露出的槽位直接跳过。
- 验收补一条：CJK 正文 + 槽位覆盖的渲染测试（宽字符不被切裂）。
- 槽位字形全部是宽 1 字符（braille 转轮 / `▌` / `█░`）；但**被覆盖的 cell 必须是预留占位**（见上），否则槽位字形宽 1 也不能保证不切裂底下的宽字符。
- 效果：流式且 delta 未到达时 **rebuild = 0**；Tick 只画几个 cell。「每帧 O(回合)」→「每帧 O(可见动画槽位)」。

### 3.4 流式尾部增量（Open 块）

- 仅 **text 块**维护 `wrapped_prefix: Vec<Arc<str>>` + 尾部 partial line；delta 只重折最后一行。
- r2：reasoning 退出 transcript 管线（§4.4 活动区 + §4.6 聚合），本节的复杂度只剩 text 块。
- seal 时整块重渲一次（此时才上 markdown/syntect）。
- **r4 已落地**（T7），实现形态相对本节原桳有两点演进：
  - 折行内核抽为 **`render_line::WrapState`**（可续算状态机），`wrap_text` 即「喿入全部文本后取
    行序列」——增量与一次性的逐行等价由同一算法**结构性成立**，锁
    `wrap_stream_incremental_matches_one_shot`（含 ▌ 视图分解）；
  - 前缀存 **`Arc<[RenderLine]>`**（渲染体而非裸字符串）：跨 delta 零拷贝共享，仅折行
    事件重建切片；尾行 1–2 行（▌ 折出至多 1 行封口 + 当前行）每 delta 重建。光标由
    `cursor_view()` 按同一规则虚拟喿入——canonical 状态机只吃正文（实测把 ▌ 喂进
    状态机再回退会与纯文本状态分叉，case：`"abc d"` @ width 3）；
  - bench ④（附录 A.2）：8KB 正文逐 delta **3µs vs 全量重折 479µs（≈160×）**。

### 3.5 帧调度与节流

- `App` 增加 `dirty` 标记：**由 handle() 的可见状态变更驱动**，而不是由消息来源驱动。
  Runtime/Action/Key/Mouse/Paste/Resize 一律置位；Tick 在 `handle_tick` 中处理 toast
  过期（6s）、`quit_armed` 复位（3s）、首页列表刷新（3s）等**可见副作用**，因此 Tick
  同样必须走「有变更才置位」判定——否则 toast / 双击退出提示会冻在屏幕上。纯动画帧
  只覆盖 `AnimSlot`，不置 dirty。
- SSE 引起的重绘钳到 ~20fps（合帧不合并状态）；按键类事件立即绘（输入延迟优先）。
- 主循环改为 `if dirty { ensure; draw; dirty=false }`（`main.rs:128-151`）。

## 4. 工具与思考的 UI（M2）

### 4.1 ToolView 分派（替代字符串 match）

```rust
pub enum ToolViewKind { Shell, Edit, Read, Search, WebFetch, WebSearch, Panel, Spawn, Generic }
// 每个 view: header(&ToolViewData, w) -> RenderLine; body(..., expanded) -> Vec<RenderLine>
```

- `is_panel_owned_tool` / `is_shell_tool` / `tool_icon` 等特判全部收编进 view 实现。
- 补偿解析（`extract_shell_output_text` / `shell_meta_from_raw` / `pretty_json_output` / `format_args_preview`…）只在 `ToolViewData::parse` 里跑一次并缓存；U-10 落地后该层整体删除。

### 4.2 工具运行组（run group）

- 一个 round 内**连续的 Tool 块**默认折叠为一行：

  `┃ ⚙ 12 tool calls · 10✓ 1✗ 1⊘ · 3.2s · F7 展开`

- **失败例外**：组内最后一张 Failed 卡始终内联展示（错误不许藏）。
- 展开态为卡片列表；展开态记 `expanded_groups`。多工具回合默认高度 O(工具数×卡高) → O(1)。

### 4.3 卡片三态渲染

| 态 | 渲染 |
|---|---|
| Running | 标题 + spinner 槽位 + 进度尾窗(≤6 行) + `↓ 12.3 KB`（`progress_bytes_total`，跨仓契约 §5 已定义）+ 耗时；不渲 args/diff/展开钮 |
| Sealed ✓ | 标题 + metrics 一行（exit/duration）；body 按组/卡展开态 |
| Failed | 标题 + ✗ + 失败摘要；diff/输出完整可见 |

`is_default_expanded` 词表**删除**——「默认展开」的职责交给运行组；单卡内部输出仍有 8/24 行帽 + 展开态（决策项 D3）。

- 内容优先级：`思考 marquee > 运行中工具（icon + name + 耗时 + ↓bytes）> 空闲`；多轮回合里思考与工具交替，永远回答「现在在干嘛」。

### 4.5 思考浮层与回放（机主决策 ①）

- **Ctrl+T**：显示**当前回合**的完整思考（body 在内存，零抓取），只读浮层复用 overlay 栈，Esc 关闭。
- **历史思考**：渲染层废弃；需要时拉完整回放——从 daemon 按时间线分页重取进入只读浮层，即取即弃。
- ⚠ **回放边界（对齐跨仓契约 D6）**：v1 无按需回取端点——未 offload 的近端回合走现有 timeline 分页可取全文；已 offload 的远端回合只有预览壳，浮层内如实标注。全文回放与 `timeline.tool_output` 同批进入 v2 立项。
- **键位冲突（D5，已裁决 r3：方案 A）**：Ctrl+T → 思考浮层；新建会话改绑 **Ctrl+N**（README 键位表随 M2 更新）。跟随 Codex 肌肉记忆，代价是浏览器式 Ctrl+T=新建的旧习惯需要迁移。
- 退出前总览（Codex 在 Ctrl+C 前的一次性总览）：M4，复用回放浮层。

### 4.6 回合头聚合元数据（B1 载体，零行成本）

回合头一行内追加聚合：`──── turn 12 · 思考 6 段/412 行 · 8 工具(2✗) · ✓`。seal 时写入 `TurnSeg` 计数字段并纳入 `struct_key`——每次 seal 只重渲本回合头一次。丢弃有计数、信息有回放（§4.5），B1 闭环。

### 4.7 渲染分层与「查看更早消息」（机主决策 ②③）

| Tier | 语义 | 工具 |
|---|---|---|
| T1 调用行 | 永远一行、无可展开 body，信息从 **args** 提炼 | `todo_write/todo_update`（`⚙ todo_update T3 → in_progress`）、`todo_list`（`⚙ todo_list · 12 项`）、`skills`（`→ skills xxx 已载入`）、`spawn_subagent`（`│ spawn <name>`） |

- 机主决策 ③：**无 T0**——panel-owned 工具维持现「单行」实现并按上表优化（信息从 args 提炼，不碰输出）。
- 工具卡继续滚动在 chatview；**视口外卸载**由虚拟化承担（块级化后粒度更细）；输出源数据的卸载依赖回取端点（v1 不做）→ 不进 M3。

## 5. 数据面契约（M3）

> 展示字段的最终定义以
> [`qaqh-backend/docs/spec/2026-09-18-工具结果展示契约-v1-spec.md`](../../../qaqh-backend/docs/spec/2026-09-18-工具结果展示契约-v1-spec.md)
> 为准。本节只列 TUI 的消费要求与依赖顺序，**不再自定义 wire 结构**。

1. **类型化工具投影（U-10 核心）**：`TimelineTool.display`（可选）提供
   `summary` / `diff` / `header` / `body` / `metrics`。TUI 命中即按变体渲染；
   缺失或 `Unknown` 变体时**完整回退**旧字段（跨仓契约 H16），不得部分解析。
2. **progress 元数据**：`progress_bytes_total`（累计观测字节）与 `progress_stream`
   （开放字符串）进 wire，运行卡显示 `↓ 12.3 KB`；终态 `body.output` 的 `\r`/ANSI
   归一化由后端负责，流式 progress 维持现状由 `apply_bash_progress` 渲染覆盖语义
   （跨仓契约 §5.2 v1.1 修订：流式字节无法在后端撤回）。
3. **按需回取**：v1 **不做** `timeline.tool_output`（跨仓契约 §9 D6）。截断以
   `truncated: true` + `output_bytes` 明确标注（B1：丢弃必须可见）；全文回取作为
   v2 候选，需先定内容存储的保留期/鉴权/GC。**思考回取同批立项**（r2）：offload 后
   reasoning 仅预览壳，历史回放（§4.5）对远端回合降级为预览。
4. **workspace 改造对齐点**（不变）：
   - `DashboardSnapshot` 字段稳定性/携带 schema 版本号，TUI 按 version 降级渲染；
   - todo 条目 `evidence` 建议带上限（侧栏单行展示用）；
   - 推送节奏维持事件驱动（todo 工具调用即时推送），勿改为轮询。
5. **删除 gate**：每删除一个前端解析器前，必须先确认其覆盖的**全部工具族**都已产出
   对应 display 变体并有该族快照测试；最终 gate 为全仓工具展示路径
   `serde_json::from_str` 8 → 0（含 `subagent.rs`）。

## 7. 风险与不变式

1. **两级缓存键漂移**是最大回归源 → §3.7 的锁以 `#[ignore]` 先于实现合入，实现后逐一摘除（门禁保持全绿）。
2. **动画槽位纪律**：槽位 cell 必须是折行时预留的占位空格，覆盖前校验 `cell_width()==1`；CJK 用例锁死（§3.3/§3.7-8）。
3. **B1（丢弃必须可见）**：所有折叠/截断/省略必须带计数标注（v1 用 `truncated` +
   `output_bytes`/`progress_truncated`）；全文回取入口延后到 v2（跨仓契约 §9 D6），
   不作为 M3 的阻塞依赖。
4. **行为等价的验证口径**：M1 以「F3 全展开 + 组全展开」的渲染输出为准做逐行 diff——密度变化（M2）允许输出变短，但信息不得静默丢失。
5. **D1/D5 已裁决**：D1 = 渲染废弃 + 活动区 + 回放；D5 = 方案 A（Ctrl+T 浮层 / Ctrl+N 新建）。不变式：reducer 丢 sealed reasoning body 必须幂等且计数可见（debug stats，不进 UI）。
6. **契约漂移协议（r3，后端已开工）**：对齐以 **wire 实测** 为准，文档与 wire 冲突时以 wire 为准并回写 spec；每个前端解析器删除前，必须先有其覆盖工具族的 **wire fixture 快照测试**（与 §5.2 的 8→0 gate 叠加，fixture 变更需在 PR 中可见）。
