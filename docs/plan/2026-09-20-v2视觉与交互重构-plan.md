## 0. 执行摘要

v1 已证明功能与协议链路可行：多会话、子代理观测、workspace、权限/ask/plan、工具投影、
块级缓存与虚拟化均已落地。但 v1 的视觉与交互形态是「终端 IDE / 控制台」：
chrome 多、边框重、信息密度高、历史滚动与虚拟化复杂，且主题色散落在多个 UI 模块中。

v2 的目标不是继续给 v1 打补丁，而是以 **terminal-native、chat-first、low-chrome**
为方向，参考 Grok Build 的视觉语言，重构 QAQH 的默认 agent 体验：

- 已提交历史交给终端 scrollback；
- 底部保留 inline live viewport，承载流式内容、composer、状态与快捷键；
- 复杂管理面（会话、设置、帮助、workspace、权限/ask/plan）走 alternate-screen 工作区；
- 主题、间距、层级、markdown、工具块统一到语义 token；
- 保留 QAQH 的多会话、子代理、workspace 与后端契约能力，不复制 Grok 品牌与实现。

v2 是**交互模型重构**，不是换肤。最大的产品决策是：是否接受「单活动会话 + 工作区切换」
来换取终端原生滚动的完整收益；如果坚持常驻多 tab + 常驻 sidebar，收益会被显著削弱。

## 1. 项目章程

### 1.1 背景

v1 当前采用 `ratatui::init()` 的 alternate screen 全屏模式，App 自己维护：

- `scroll.follow` / `scroll.offset`；
- `ui::viewport_top()` / `TranscriptCache::window()` / `ScrollbarState`；
- `keep_turn_range()` / `evict_turn()` / 离屏估算；
- `estimate_block_lines()` 与首帧几何不变式。

`W-09` / `W-11` 这类缺陷本质上来自「全屏自绘滚动 + 虚拟化 + 估算高度」的组合。
继续优化 v1 可以收敛局部问题，但无法消除这类系统性复杂度。

### 1.2 目标

| ID | 目标 | 衡量 |
|---|---|---|
| G1 | 让对话成为第一视觉主体 | 默认 agent view 无持久 tab/sidebar 抢焦点 |
| G2 | 采用终端原生 scrollback 承载已提交历史 | 不再自绘历史滚动条与滚动窗口 |
| G3 | 建立统一语义主题系统 | v2 UI 无硬编码颜色；支持 dark / light / terminal / auto |
| G4 | 降低 v1 滚动与虚拟化复杂度 | `estimates` / 历史窗口 / 离屏淘汰大面积退役 |
| G5 | 保留 QAQH 差异化能力 | 多会话、子代理、workspace、权限/ask/plan 全可用 |
| G6 | 与后端锚点解耦 | v2 不改 qaqh.Ringing v1；后端漂移单独适配 |
| G7 | 可渐进迁移、可回滚 | feature flag + v1/v2 并行验证 |

### 1.3 非目标

- 不修改 `qaqh-backend` 协议、daemon、`qaqh-client` 契约。
- 不整体复制 Grok 代码、品牌、logo、文案或默认交互。
- 不在 v2 第一阶段删除多会话/workspace/子代理能力。
- 不追求「所有终端行为一致」；以兼容矩阵定义可接受边界。
- 不把 v2 做成纯 stdout CLI；仍需交互 composer、modal 与状态栏。

### 1.4 成功标准

- 默认 agent view 使用 inline viewport，已提交历史进入终端 scrollback。
- 已提交内容不重复、不丢失；重连/re-baseline 幂等。
- resize、主题切换、会话切换有明确行为定义，并进入测试矩阵。
- 主题 token 覆盖全部 v2 UI；16 色 / 256 色 / truecolor 降级可用。
- 核心流程与 v1 等价：新建、发送、流式、工具、权限、ask、plan、切会话、子代理、导出。
- 长会话内存与滚动性能不劣于 v1，且 UI 层历史驻留显著下降。

### 1.5 范围

**In scope**

- 默认 agent view 的终端模型、视觉系统、信息架构与交互重构。
- 主题 token、palette、markdown、工具块、composer、status、shortcuts。
- alternate-screen 工作区：会话列表、设置、帮助、workspace、子代理、权限/ask/plan。
- 迁移、feature flag、兼容矩阵、性能/内存回归、文档。

**Out of scope**

- 后端协议变更、服务面扩展、timeline 数据模型重写。
- 安装器、打包、发布渠道。
- 非终端平台（web/桌面 GUI）。

## 2. 体验模型

### 2.1 三种界面模式

| 模式 | 终端行为 | 用途 |
|---|---|---|
| Agent View | Inline viewport + 终端 scrollback | 默认对话、流式、工具、composer |
| Workspace View | Alternate screen | 会话列表、设置、帮助、workspace、子代理 |
| Modal View | Alternate screen overlay / bottom panel | 权限、ask、plan、确认、选择器 |

Agent View 是 v2 的主界面；Workspace/Modal 只在需要时接管屏幕，退出后回到 Agent View。

### 2.2 会话模型

推荐采用 Grok 式「**单活动会话 + 工作区切换**」：

- 任意时刻只有一条 agent 流占据主视口；
- 多会话在后台保留，切换通过会话选择器或命令面板；
- 子代理观测是独立工作区视图，不污染父会话 scrollback；
- 是否保留常驻 tab bar 是待裁决项 D2。

### 2.3 信息架构

```text
Agent View
  ├─ 终端 scrollback（已提交历史）
  │   ├─ UserPrompt
  │   ├─ AssistantMessage
  │   ├─ ThinkingLine
  │   ├─ ToolBlock / ToolGroup
  │   └─ SystemEvent
  └─ Inline live viewport
      ├─ in-flight block
      ├─ composer
      ├─ activity line
      └─ status / shortcuts
```

### 2.4 交互模型

- 键盘优先；鼠标是增强，不阻塞主流程。
- `/`、`@`、`!` 模式在 composer 内完成。
- 动态 shortcuts bar 根据当前上下文变化。
- 复杂操作进入 Workspace View；快速确认进入 Modal View。
- 任何「丢弃/折叠/截断」仍遵守 B1：必须可见、有计数、有回放入口。

## 3. 视觉系统

### 3.1 设计原则

1. **Content over chrome**：正文优先，边框和提示不抢注意力。
2. **One accent**：主强调色克制使用；语义色只表达状态。
3. **Semantic tokens**：颜色、间距、边框、markdown 都来自 token，不散落硬编码。
4. **Terminal-native**：尊重终端背景、调色板、选择、复制与滚动。
5. **Progressive disclosure**：默认低密度，复杂信息按需展开。
6. **Append-only history**：已提交内容不重写；可变内容只存在 live viewport。
7. **CJK-first**：宽度、折行、占位、动画槽位以中文终端为第一等公民。

### 3.2 主题 Token

主题结构至少覆盖：

- surface：`bg_base` / `bg_light` / `bg_dark` / `bg_highlight` / `bg_hover`
- text：`text_primary` / `text_secondary` / `gray_dim` / `gray` / `gray_bright`
- accent：`accent_user` / `accent_assistant` / `accent_thinking` / `accent_tool` /
  `accent_system` / `accent_error` / `accent_success` / `accent_running`
- semantic：`command` / `path` / `warning` / `plan` / `verify`
- chrome：`border` / `border_active` / `selection` / `scrollbar`
- diff：`diff_add_fg` / `diff_add_bg` / `diff_del_fg` / `diff_del_bg`
- markdown：heading 1-6 / code / inline code / link / quote / rule / table

### 3.3 主题集

| 主题 | 定位 | 说明 |
|---|---|---|
| QAQH Night | 默认 | 近黑 surface + 克制强调色，参考 GrokNight 但不复制品牌 |
| QAQH Day | 亮色 | 亮背景可读，覆盖同一 token 集 |
| Terminal | 终端原生 | 不画 surface，沿用终端 16 色，反色表达选中 |
| Auto | 系统跟随 | 根据系统明暗解析到 Night / Day |

颜色能力：truecolor → 256 → 16 色降级；支持 `NO_COLOR`。

### 3.4 组件清单

- `UserPrompt`：accent rail + 填充色带 + 时间戳
- `AssistantMessage`：单列 markdown，accent rail，低 chrome
- `ThinkingLine`：轻量单行，运行中可动画，seal 后折叠为计数
- `ToolBlock` / `ToolGroup`：执行记录融入对话流，失败内联
- `TurnDivider`：弱分割，不抢正文
- `Composer`：轻边框输入区，内联 model / mode / attachment
- `StatusLine`：连接、usage、activity、clock
- `ShortcutsBar`：上下文动态提示
- `Modal` / `WorkspacePane`：alternate-screen 统一组件

### 3.5 排版与间距

- 默认单列，正文宽度受终端宽度约束。
- 块间距使用空行而非重边框。
- 标题、正文、元信息通过颜色/字重/缩进分层。
- 终端宽度不足时优先保正文，再降级 chrome。

### 3.6 动效

- 动画只存在于 live viewport：spinner、progress、thinking。
- 已提交历史不含动画。
- 动画不进入渲染缓存键，不触发历史重绘。
- 终端不支持或 `NO_COLOR` 时退化为静态 glyph。

## 4. 技术架构

### 4.1 终端模型

v2 采用 **hybrid inline**：

```text
stdout / terminal scrollback
  ← commit sealed blocks once

inline viewport (ratatui Viewport::Inline)
  ← live block + composer + activity + status
```

- `ratatui 0.30` 原生支持 `Viewport::Inline` / `init_with_options`，作为起点。
- Grok 的 `xai-ratatui-inline` 作为 resize / scrollback / re-render 参考实现。
- 复杂管理面临时切 alternate screen；返回时恢复 inline viewport。

### 4.2 提交协议

每个可提交块具有稳定 `commit_id`：

```text
live -> sealed -> committed
```

- `live`：只在 inline viewport 内重绘；
- `sealed`：内容冻结，生成 ANSI 行；
- `committed`：emit 到 scrollback，写入 ledger；
- 重连/re-baseline 先查 ledger，禁止重复 emit。

### 4.3 模块规划

建议新增/重构为：

```text
src/terminal/
  inline.rs        // Viewport::Inline 生命周期
  commit.rs        // commit ledger / emit / 幂等
  resize.rs        // resize 策略与 re-render

src/theme/
  mod.rs           // Theme token + 解析 + 缓存
  color_support.rs // truecolor / 256 / 16 色 / NO_COLOR
  night.rs day.rs terminal.rs
  markdown.rs

src/ui/v2/
  agent.rs         // Agent View
  transcript.rs    // commit 渲染适配
  composer.rs
  status.rs
  shortcuts.rs
  workspace.rs
  modal.rs
```

v1 `src/ui/` 保留到迁移完成；通过 feature flag 并行运行。

### 4.4 退役清单（迁移完成后）

- `src/app/render/estimates.rs`
- `TranscriptCache` 中历史窗口/淘汰/总行数部分
- `src/ui/transcript.rs` 的自绘滚动条与窗口逻辑
- `transcript_ops.rs` 的 scroll/follow/top/bottom
- `ui::viewport_top()` 与历史几何锁
- `W-09` / `W-11` 相关估算锁（由 commit 协议锁替代）

### 4.5 后端边界

- 后端锚点冻结为 `qaqh-backend @ 5ec1900d6c937b6ff927d8f65fcd37d465de7988`（后端 `betav2`
  tip；2026-09-23 刷新，取代 09-20 的 `50d3dc1`。本次刷新只带来 `ConversationSendMessage`

- 默认 agent view 无重边框、无多焦点 chrome。
- 所有颜色、间距、边框来自 token。
- markdown、工具、diff、状态、composer 视觉一致。
- 16 色 / 256 色 / truecolor / NO_COLOR 均可读。

### 6.3 终端兼容矩阵

至少覆盖：

- Windows Terminal / PowerShell
- WezTerm
- iTerm2
- Alacritty
- Kitty
- GNOME Terminal / Konsole
- tmux / SSH

每个终端记录：scrollback、resize、truecolor、鼠标、复制、inline viewport 行为。

### 6.4 性能与内存

- 首帧延迟不劣于 v1 基线。
- 流式 delta 不重绘历史。
- 长会话 UI 层驻留显著低于 v1。
- commit / emit / resize 基准纳入回归。

### 6.5 测试策略

- 单元：token、commit ledger、ANSI 渲染、状态机。
- 快照：TestBackend / golden buffer。
- 集成：真实 daemon + 真实终端 PTY。
- 兼容：终端矩阵脚本化冒烟。
- 回归：v1/v2 parity matrix。
- 证伪：每个关键锁必须有「故意破坏会变红」的说明。

- 每个切片必须有：目标、范围、非目标、验收、回滚。

- v1/v2 并行期间，v1 只做阻塞修复，不新增视觉功能。

### 7.4 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 终端 reflow 行为不一致 | 高 | 兼容矩阵 + resize purge/re-render |
| 多 tab 与 scrollback 冲突 | 高 | D2 决策；必要时工作区切换 |
| 历史重放不完整 | 高 | commit ledger + 完整模型或降级策略 |
| 主题切换无法重染历史 | 中 | 清屏重放或接受历史旧色 |
| 鼠标捕获影响选择复制 | 中 | 模式切换或 Shift 说明 |
| 输出速率/背压 | 中 | 批量 emit + 流控 |
| 范围膨胀 | 高 | 里程碑门禁 + 非目标 |
| 后端漂移 | 中 | 锚点冻结 + 批量适配 |
| 许可/品牌 | 中 | 不复制品牌；代码复用走 Apache-2.0 流程 |

### 7.5 发布与回滚

- 用 feature flag 并行 v1/v2。
- 先 dogfood，再切换默认。
- 保留 v1 回退入口至少一个发布周期。
- 清理 v1 滚动路径前必须验证回滚路径。
