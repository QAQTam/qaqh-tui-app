## 0f. 合并演练结果（2026-09-17，临时分支实测，未推送）

6 个 PR 都从 `809e317` 分出且改动面重叠，**串行合并会冲突**。我在临时分支上真实跑了两轮（第二轮在 NPC 审查返工之后），结论如下。

### 第二轮（按下方推荐顺序，返工后的 head）

**只剩一处冲突点，涉及 3 个文件**，且合并后门禁全绿：

```
cargo test --all-targets                     # 194 passed / 0 failed
cargo clippy --all-targets -- -D warnings    # 零 warning
cargo fmt --check                            # 干净
```

194 = 148（基线）+ 7（subagent）+ 24（ui）+ 10（session）+ 5（deps），**逐项对得上，无测试被静默吞掉**。

| 冲突点 | 解法 |
|---|---|
| `mod.rs` 顶部 `use crate::runtime::{…}` | 合并成一行：`{ConnEvent, Runtime, RuntimeMsg, StreamKey, TimelineLostReason}` |
| `mod.rs` 的 `#[cfg(test)] mod tests` | 两边内容都留。两侧各自最后一个测试函数的 `}` 原本由公共上下文提供，**必须给先出现的那侧补一个 `}`**，否则 `unclosed delimiter` |
| `session_ops.rs` 的测试模块 | 一侧含**新增生产函数** `apply_rejected_ack`，另一侧只有测试模块 → 保留生产代码，把**两个测试模块合成一个**（直接拼接会 `E0428 the name 'tests' is defined multiple times`） |
| `runtime.rs` 的 `TimelineStatus::Closed` | **语义冲突，必须「合并」而非「二选一」**，见下 |

> ⚠ **最阴的一处**：`runtime.rs` 那个 hunk，git **只把 `seed` 那一行判成冲突**，而 `error:` / `reason:` 那一行被**自动解成了 ours**。于是冲突现场看起来"很好解"，解完却 `E0559: variant TimelineLost has no field named 'error'`。正确形态是把两边**合起来**：
> ```rust
> seed: seed.clone(),                                            // ui 侧：其后还要用 seed 发 StreamRecovered
> reason: TimelineLostReason::Other(format!("timeline 流结束：{reason}")),  // subagent 侧：结构化载荷
> ```
> **教训**：冲突标记的**范围**不等于语义冲突的范围；自动解掉的那几行同样要核对。合并后请务必 `rg "TimelineLost \{" -A 4 src/` 确认字段名全局一致。

> 另一条：合并后 `cargo fmt --check` 报的那处偏差是**合并脚本自身的产物**（拼接两侧内容时吃掉了 `use` 行的缩进），不是分支的问题。合并后仍建议跑一次 fmt。
